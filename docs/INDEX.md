# Docs Index

System documentation for the multiplayer stack. Read this, then load only what
the current task needs.

Current state: **client-authoritative rooms on Colyseus (ADR 0011 + 0013), with a data-driven
content pipeline (ADR 0014).** Each client simulates its own entity and reports state; the
server (a Colyseus `Room`) relays peers, interpolated on a clock-synced timeline — no
`@colyseus/schema`. Product framing: an "extremely simplified Roblox" — a platform hosting a few
**modes** that share one stack. **Parkour** is the first game (`modes/parkour`), and what a game contributes to the platform is one `ModeDescriptor` (`@mp/mode`, ADR 0052). One `GameRoom` serves them all; which game a room is for is a matchmaking filter.

Content is **data** (`@mp/content`): levels are a tree of **nodes**, and a node holds a **list of
components** — `Collider`, `Mesh`, `Renderer`, `Light`, `Track`, `Bumper`, `Checkpoint`, … — each a declared set of parameters
(ADR 0035). `Piece` and `PrefabInstance` merged into one `Node`; the loader
reads the seven engine components and hands a mode every component on the node that owns the collider you
touched, so adding a gameplay rule touches only its definition and the mode. Geometry is **authored data only** — the code kit and its generators are deleted (ADR 0027). Rendered
by a polished shared pipeline (`@mp/render-three`: IBL, ACES, soft shadows, GTAO/SMAA/bloom).
A gameplay rule is a **component on the node whose collider you touched**, detected by real engine contact. Inspect it locally
with the **viewer** (`tools/viewer`, `pnpm dev:viewer`); author it in the **editor** (`tools/editor`,
`pnpm dev:editor`, ADR 0023), which is the content path. The parkour mode **loads a level by name** —
`?level=<file>` from `content/levels/`, no param → **`default.json`**, a placeholder level so the game
always boots, editable in the editor like any other file (ADR 0027). The name also filters matchmaking,
so a room only holds clients on one level. Server stays content-free.

Wire is delta + quantized snapshots (v10: position + a state-flags byte — grounded/rising for animation, dead for the ragdoll — plus facing, locomotion-speed and movement-base bytes, none derivable from a position curve; while the base is set the transform is in that platform's frame — ADR 0021); budgets 2 & 3 validated with bots. Colyseus pinned to
**0.16** (matched client/server); default `ws` transport (uWS is a later swap); scale-out infra
(Redis/multi-region) deferred to deploy. History: server-authoritative through M10 (ADR 0011
reversed it); ball demo retired (tag `m10`); world/controller relocated out of `@mp/server/tps`
(ADR 0014). **M9 (2D path)** remains deferred (SEED §7).

The decision lives in `modes/parkour/src/cameraOcclusion.ts`, pure with the queries injected, so it is tested against slabs on a number line. **Three sightlines, not one**: the camera aims level with the top of the head, so a platform can lie across the whole body with the head clear above it — two extra probes down the capsule's spine catch it, which is what most third-person cameras do and cheaper than frustum-corner casts (Roblox's Popper), whose fan spreads *away* from the character and still misses a narrow beam between the rays. **Only the meshes a cast names wear the hole** (`levelView.setOccluders`, via the new `VisualItem.colliderHandles`), each getting a masked **copy** of its material — materials are cached by asset id and shared, so patching in place would fade the whole level. That copy-per-occluder is the third design; the two before it tried to keep the hole off the floor from inside the shader and both shipped artifacts, because **no test on a fragment's position can separate the platform overhead from the floor beside the character's feet** — from a high camera the floor is both nearer to the eye and right beside the sight line. The hole is a **cone** (constant angle, so constant size on screen at any zoom) centred on the capsule's middle rather than the aim point, **dithered** with interleaved gradient noise rather than alpha (opaque, no sorting; not Bayer, since Three compiles GLSL ES 1.00 which forbids dynamic array indexing), and animated by **growing the radius** rather than the strength, so the interior is cut from the first frame and stipple only ever lives in the moving rim. **AO had to be told and shadows had to be left alone**: GTAO reads its own depth prepass, which never saw the discard, so the character came out wearing occlusion cast by a platform the player cannot see — `PostFXOptions.aoIgnores` hides the occluders for that one pass. Shadows stay: a surface whose pixels are gone still shades the level, and a hole in a shadow is not a thing. Two diagnostic checkboxes (`sun shadows`, `ambient occl.`) earned their place immediately — the artifact that survived four fixes was AO, and one toggle proved it in seconds. Known open: frame-edge clipping (ADR 0020's, still), the dither swimming with camera motion, and the camera still able to sit in a neighbouring interior. Every dead end is written down — the plane cut that made a half circle, the depth slab that made a band on oblique surfaces, the thickness allowance that flip-flopped as the camera orbited, the footing-collider rule that collapsed the camera into the head, the pitch clamp that froze the orbit, the hit-height test that was unreachable, and the shadow-map hole that cast a beam from the sun)

## Built

- `core` — math (incl. quaternion helpers), entity model, fixed-timestep loop, `createSimClock` (fixed-step content time, slewed to a reference clock), transport interface. Also owns **`InputCommand`** since ADR 0061 — it was never sent on the wire, and keeping it in `@mp/net` meant the component system could not name it without depending on the netcode. `actions` carries a game’s own action names. Owns the **simulation tick** since ADR 0062 (`TICK_RATE_HZ`/`TICK_DT`, in `tick.ts`) — it was in `@mp/character`, so every host imported a character package to learn how fast the world runs. One rate for every game: peers share a synced clock and per-tick base indices, so two rates would be two protocols.
- `net` — binary codecs (v10): snapshot (delta + quantized), welcome, state, ping/pong, roster; quantization utils (position, facing, speed). `NET_CHANNEL` is the Colyseus channel they ride. Bits 3..7 of the state byte are the **game’s** since ADR 0064 (`STATE_GAME_SHIFT`/`_BITS`/`_MASK`, `packStates`/`unpackStates` in `gameStates.ts`) — five booleans in a byte already being sent, opaque to the netcode, which never learns what a name means. `InputCommand` left for `@mp/core` (ADR 0061): it was never sent on the wire.
- `physics` — Rapier3d wrapper: dynamic/fixed/kinematic bodies (position + rotation, linear + angular velocity), **kinematic character controller** (contact reporting + a downward `probeGround`), a general **sphere cast** (`castSphere`, with self-exclusion and on-demand query-index refresh), a **sphere overlap** (`sphereOverlaps` — "is this spot free", which a cast cannot answer since `castSphere` ignores an overlap it is leaving; ADR 0055), **collision layers** (`CollisionLayers`, applied to the controller's own queries too), and **triggers** (`BodyOptions.sensor`, ADR 0054: detected on overlap, resolving nothing — so `EXCLUDE_SENSORS` on the controller's move, on `probeGround` and on `castSphere`, and a separate `CharacterBody.overlaps()` shape query with `EXCLUDE_SOLIDS` to find them, since a sensor by definition never reaches `collisions`). Headless + browser.
- `humanoid` — the stack-level kinematic character controller (`stepCharacter`, `CharacterTuning`; ADR 0012), mode-agnostic. **Jump feel** (ADR 0034/0035): the vertical step is the exact trapezoid `½(v₀+v₁)·dt` — except while settling on a surface, where the full `v·dt` is the contact nudge and making it "exact" destabilises the controller's horizontal resolve — so `jumpHeight` is the measured apex to 0.2%; `jumpBuffer` mirrors `coyote` (early presses and one-tick taps both survive); `liftVel`/`liftStore` hand a departed mover's velocity to a late jump; `fallGravityScale` 1.6 / `apexGravityScale` 0.5 / `jumpCutScale` 0.4 shape the arc (each reverts to 1), and the apex float is gated on having no ground underfoot because a resting character sits at `vy = 0` inside any apex window. Earlier: the jump gate is `grounded || coyote > 0` off a countdown refilled with footing and spent on leaving, so a press just past a ledge still fires and one ledge is still one jump; `move`'s new `ceiling` flag ends the rise under a roof instead of leaving `vy` positive with nowhere to go; `maxFallSpeed` bounds the fall on a level with no kill plane. Relocated out of `@mp/server/tps`. **Platform carry** (movement base): rides a moving piece by keeping its position in that surface's frame (`PlatformPoseLookup`), and a jump off a mover inherits its velocity. `CharacterState.launch` is an upward speed something outside locomotion asks for and the step **consumes** (a bumper, ADR 0032): it joins `jumping` as `leaving`, which is what releases the ride, the footing and the movement base — a launch written onto `vy` from outside would be zeroed by the ride on the next tick. Paired with the loader's frozen posing — see `docs/physics.md`. Also the **blocky 11-part rig** (torso split at the waist) (`RIG`, proportions derived from the capsule) and its **procedural animator** (`createAnimator`): distance-driven stride, two-bone analytic IK, half-life smoothing. No skinning, no clips, no art; headless and unit-tested (ADR 0018). **Locomotion is a component a game attaches** since ADR 0061: `createLocomotion(deps, type?)` returns a def whose `onLocomote` calls `stepCharacter` (untouched, 119 tests unchanged), built per session so it closes over the live character; `LOCOMOTION_DEF` is the unbound copy a registry holds for tools. No params on purpose — tuning stays the mode’s one live object. This package no longer depends on `@mp/net`. `AnimatorFactory` (`(gait, seed) => Animator`) is the shape a game supplies to replace the gait (ADR 0063) — `createAnimator` *is* that shape, so the default is the function itself. `AnimatorFactory` takes a per-character states reader since ADR 0064, so one animator body animates both the local player (states from the game) and a peer (states off the wire). `CharacterTuning.groundMaxAccel`/`airMaxAccel` cap horizontal acceleration in m/s² for a game whose speed climbs; off by default (ADR 0078). `GaitTuning.inertiaAccelCap` bounds what the inertia layer believes, `maxStrideRate` the legs’ cadence, `inertiaLateral` scales the layer’s sideways response, and an arm never rolls inward past vertical (ADR 0079).
- `content` — data-driven content. **The schema is nodes and components** (ADR 0035): `Node` = transform + `components: ComponentData[]` + `children` + an optional `prefab` reference with `overrides`; `Level` = a node forest plus a prefab table of root nodes. `nodes.ts` holds the six type names the engine itself reads (`COLLIDER`/`MESH`/`RENDERER`/`MATERIAL_OVERRIDE`/`TRACK`/`SPAWN`), the parameter readers, `effectiveNode` (a placement resolved against its prefab: overrides applied, the placement's own singletons beating the prefab's, its children appended after the inherited ones), `bakeOverrides` and `walkNodes`. `LevelConfig.environment` holds sun, ambient, sky **and `postfx`** (ADR 0048, ADR 0057) — one block because they are tuned against each other, every part optional so absent is never an error. `validate.ts` checks structure always and **parameters when handed a registry** (`ParamChecker`) — the capability seam that keeps this package from depending on `@mp/components`. `loader.ts` (`instantiateLevel`) builds the world: a body and a mesh per enabled `Collider` (each at its own `center`), a `Renderer` that draws those colliders — or the `Mesh` beside it, if there is one — `MaterialOverride` cascading down the subtree, `Track` driving the frame tree, `Spawn` as a marker, and `nodeOf(colliderHandle)`/`findNode` handing a mode the node's components so the loader never names a gameplay rule. Also `freeTableKey` (a prefab table's dedupe rule) and the **keyframe track evaluator** (`track.ts`, ADR 0029: `poseAt`/`trackTime`/`easeAt`/`trackDuration`, plus the `moveTrack`/`spinTrack` presets — pure, headless, 36 tests including a proof that the presets reproduce the deleted `move` behaviour term for term. **A key is an offset from the node's transform, not a pose that replaces it** — ADR 0050: `poseAt` adds the sampled key per channel, a zero key is the rest pose, and a channel with no keys returns the authored value untouched rather than adding zero to it. That is what lets a mover be duplicated or reparented and what makes a track shareable; the presets take no base pose because of it. `Track` may name an animation asset instead of carrying keys, resolved by `keysOf` through the optional **`ClipSource`** capability `instantiateLevel` takes alongside `TypeInfo` — inline keys win, a missing clip stands still); the loader's clock (`update(now, riddenCollider?)` poses the ridden node without velocity and exposes `basePose` so riders can track it; `baseIndex`/`basePoseOf` expose clock-driven nodes as replicable movement bases — ADR 0021); and the **asset layer** (`assets.ts`, ADR 0026): kinds, `.meta` identity,
  `kindForPath`/`nameForPath`, the material schema (a shader name + tagged parameter values) and the
  **animation schema** (`AnimationAsset`/`isAnimationAsset`, `*.anim.json`, holding `keys` only — ADR 0050).
  A `Renderer` names a **material asset id** and nothing else — the `style` palette is gone (ADR 0028), and an
  unsurfaced node greyboxes. Headless, no rendering. ADR 0014.
- `components` — the component system's machinery and its built-in definitions (ADR 0035). `params.ts` is the **declaration layer**: nine parameter kinds (`number`/`bool`/`string`/`enum`/`vec3`/`asset`/`collider`/`keys`/`nodeRef`), `defaultsOf`, and `readParams` — which fills absent keys from the declaration, drops unknown ones, rejects a wrong type or a non-finite number with the parameter's path, and **validates collider shapes**, which nothing did before. `defineComponent` preserves the declaration through a `const` type parameter, so `params.loop` narrows to its own literal union. `registry.ts` is the lookup (throws on a duplicate type, hands out defaults, satisfies content's `ParamChecker` and `TypeInfo` structurally); `createRegistry` is how a **game composes its own set** (ADR 0052), and `DEFAULT_REGISTRY` is no longer what a game runs on — it is engine plus the whole shared library, kept as the fallback for a level naming an uninstalled game and as a default for tests. `engine.ts` is what the loader reads — `Collider` (repeatable, with a `center` and a `trigger` flag that makes it a sensor — ADR 0054), `Mesh` and `Renderer` (Unity's split — ADR 0039), `MaterialOverride`, `Spawn` — and `gameplay.ts` is the **shared gameplay library** a game picks from: `Checkpoint`, `Goal`, `Hazard`, `Bumper`, `Track` (whose motion is either its inline `keys` or the animation asset its `clip` names — ADR 0050), all singletons. Shared rather than parkour's (ADR 0052): several games want checkpoints and goals, so what changed was that a game **opts in** through its own registry instead of inheriting all of them. `read.ts` is the typed accessor (`componentOn(components, Bumper)?.power` is a `number`). `runtime.ts` **runs** them (ADR 0036): `createComponentRuntime(loaded, registry, { character, effects })` builds one instance per hooked component in tree order and drives `attach`/`fixedUpdate`/`contact`/`detach`; `Ctx` offers the synced tick, a seeded `random()`, the local character's `launch` and two `Effects` (`kill`, `progress`), and withholds the wall clock, `Math.random`, the network and any other player — which is what lets a hook accumulate state without desyncing, and is the wall C5 has to move. `Self` carries typed `params`, mutable `state` from `init`, `get(def)` for another component on the same node and `find(ref)` for a `nodeRef`, resolved in this placement's own scope. `Bumper`, `Checkpoint` and `Hazard` own their reaction; `Track` and `Goal` deliberately have no hook. **A component can move its own node** since ADR 0058: declare `moves` and `self.offset` is a live local-space offset from the authored transform, added to whatever a `Track` sampled, carrying colliders, visual, light and subtree — declared rather than inferred because a driven node needs a kinematic body and a place in the pose pass, decided at load. **And components can live on the player** since ADR 0059: `createComponentRuntime` takes a `PlayerEntity` from `ModeDescriptor.player`, attached after every level node, on a synthetic node with no colliders (so `onContact` never fires), a spawn-time `position`, and no `offset`. `CharacterAccess` is `position`/`velocity`/`carry`/`grounded`/`launch`/`push` over a structural `CharacterLike`, with `push` accumulating where `launch` takes the max. `PLAYER_COMPONENTS` holds `Death` — hookless data the client reads, `attachesTo: 'player'` so no editor menu offers it. `onLocomote` + `ComponentRuntime.locomote` are the **movement slot** (ADR 0061): its own call, because locomotion has to run between the host’s two physics half-steps rather than in the general sweep. `PlayerEntity.defs` are session-built definitions tried before the registry, for the player only. `HOOK_NAMES` is exported and `defineComponent` reads it, after a component carrying only the new hook was silently treated as data. `sharedComponents(names)`/`isSharedComponent`/`SHARED_COMPONENT_TYPES`: the gameplay set by name, what a game’s `content/games/<game>.json` resolves through (ADR 0077). `assetParamIds(nodes, registry, of?)`: every asset any component parameter names, for a loader to fetch (ADR 0082).
- `server` — **Colyseus** `Server` (`startServer()`) hosting one `GameRoom` for every game, matched by `filterBy(['game', 'level'])` (ADR 0052 — nothing in the room is any game, so which one it is is a filter and not a subclass): client-authoritative relay (per-client delta snapshots, no simulation, no schema), auto-join, roster/names, clock-sync ping/pong. Content-free.
- `client` — `colyseus.js` transport (`joinOrCreate`), interpolation, local authoritative controller (`localController`), clock sync, input abstraction (`.` headless + `./dom` adapters), and **touch controls** (`createTouchControls`: zone ownership by `pointerId`, re-centring stick, look/pinch/tap channels — headless and unit-tested; ADR 0022). The touch controls track the stick and jump pointers as `number | null`, not `-1`: iOS Safari gives touch pointers **negative ids**, and a `>= 0` test read a real thumb as no thumb — the knob followed it and the character stood still (found on Kodjo’s iPhone; Chrome’s emulation uses positive ids).
- `render-three` — WebGL2 stage (+ an explicit `resize()`, for a canvas sized by a panel layout rather than the window) + the polished greybox pipeline (IBL, ACES, soft shadows, GTAO/SMAA/bloom, level-view). `environment.ts` owns **the sun**, and it is one input (ADR 0046): `sunElevation`/`sunAzimuth` drive the key light, its shadow frustum, the sky bake and the environment map, with a mutable `sunAngles`/`skyParams` pair and a `refresh()` shaped for a Tweakpane binding. `environment.ts` reads `LevelConfig.environment` via `applyEnvironment` (ADR 0048) — sun, ambient and sky in one block — so nothing about how a level is lit is a constant. `lights.ts` realizes a level's **content lights** (including the `hemisphere` fill, which is a node now) (ADR 0047: `createLight`/`addLights`, shadow casters capped at 4 because a caster is an extra scene render and a point light is six; the sun is not one of these). `sky.ts` is the **sky**: a hand-written gradient shader (monotonic `mix` over `pow` of height, plus a sun glow and disc) baked to a 512-per-face half-float cubemap that serves as both `scene.background` and the PMREM source, with `sunDirection` and `skyUniformValues` pure and tested. Lighting is dialled to `environmentIntensity` 0.2 against a white-over-grey `HemisphereLight` at 0.4, because a saturated sky lights blue 21x red. `installSky`/`loadSky` still load an equirect texture, kept only as the backdrop toggle the procedural sky is judged against (ADR 0045). `materials.ts` is down to `MARKER_COLORS`/`colorForMarker` (gizmo chrome), `createGreyboxMaterial()` (the no-material surface) since ADR 0028, and **the bevel** (ADR 0044: `BEVEL_RADIUS`/`BEVEL_SEGMENTS`/`bevelFor` and the `geometryForCollider` vs `outlineGeometryForCollider` split — the drawn box is a rounded cuboid, the outlined one is sharp); realizes `@mp/humanoid`'s rig as nodes (`createCharacterRig`) and applies a `Pose`, or as loose unparented meshes for a ragdoll (`createLooseParts`); re-exports THREE + OrbitControls. **Shaders, assets + thumbnails** (ADR 0026): `shaders.ts` is a registry of shader definitions that each declare their own parameters and build a Three material (`standard` → `MeshStandardMaterial`, `unlit` → `MeshBasicMaterial`, `registerShader` for custom ones) plus `compileMaterial`; `assetRuntime.ts` is the **preload pass** (textures, glTF models, compiled materials, cached by id and cloned per use) that keeps `addLevel` synchronous; `thumbnails.ts` renders an asset preview offscreen (`fitDistance` is pure and tested). `cutout.ts` is the **see-through hole** (ADR 0055): a `CutoutMask` handed to `addLevel` dithers a cone from the eye to the character, so what is in the way vanishes instead of the camera moving. `setOccluders(handles)` swaps a masked **copy** of its material onto each mesh a cast reports (found through the new `VisualItem.colliderHandles`) and puts the plain one back after — a copy because materials are shared by every piece using them, and only some are in the way. One `onBeforeCompile` across every copy, so they share a compiled program, and one shared set of uniforms driving all of them. Opt-in per view, so the editor and viewer never copy a material at all. `postfx.ts` is **level data** since ADR 0057: `config.environment.postfx` (`ao`/`bloom`/`bloomStrength`) applied through `apply(from)` onto a live public `params` a pane binds to directly, with `DEFAULT_POSTFX` as the renderer’s opinion and the GTAO pass always built so a level can switch it back on. It had been hand-written at three call sites that disagreed, so the tools did not show what you would play. It also gained `aoIgnores`, because GTAO reads its own depth prepass and never saw the discard: the character came out wearing occlusion cast by a platform that was not being drawn, so two tiny passes bracket the AO pass and hide the occluders for it. Shadows are deliberately left alone. `cutoutCoverage` is the tested copy of the geometry the GLSL transcribes; `injectCutout` is the string edit, checked against `THREE.ShaderLib` itself. Owns **`OVERLAY_LAYER`** since ADR 0065: it is an agreement between the two-pass render step (`@mp/game-client`’s scene) and every object that opts into the layer (`@mp/tps`’s nametag), and those are different packages now. `worldLabel(lines, opts)`: text standing in the world — a billboard text sprite on the overlay layer, sized in metres; `layoutLabel` is its canvas-free half (ADR 0082). `LevelView.meshesOf(handle)` answers which meshes draw a collider’s node (ADR 0082). The stage, the post-FX and the shell’s overlay size themselves from a `ResizeObserver` on the canvas, not `window.resize`: iOS fires the latter on rotation before layout settles, which left a squashed drawing buffer stretched over a screen it did not fill.
- `game-client` — **the services a browser game is built out of** (ADR 0056, ADR 0065). **Not a framework:** `startGameClient` is gone and nothing here decides what a game is. Two kinds of thing, and the difference is the point. **Must be uniform** (every client in a room has to agree or nobody sees anybody in the right place): `createNetHost` (room, clock, snapshot stream, roster, display name; synchronous with the join in flight, so `id()` is `null` for most of the first second), `loadLevelInto` (instantiate + assets + meshes + content lights + the level’s environment/post-FX, in **one** call so a level is never walkable before it is visible), `worldFromBase` (undoing a rider’s base frame — wire semantics, ADR 0021, and `rendered` vs `tick` pose is load-bearing). **Merely universal** (no agreement needed, writing them twice is waste not bug): `createScene` (stage, greybox pipeline, sky, post-FX, the nametag pass after post-FX), `createShell` (2D overlay, pause screen, touch HUD, pointer-lock-as-pause-state, resize), `createStatusLine` (line + locale together, because the line is key-driven), `levelsFor(name, registry)` (level bundling, filtered by `config.mode.name`), `localProgress(name)` (saves keyed by game so two games cannot share one), `ASSET_DB`/`CLIP_SOURCE`. Every allocator owns its `dispose` (ADR 0065 phase 0). The third-person game that used to live here — rigs, ragdolls, boom camera, walk cycle, debug pane, and the 800-line composition — is `@mp/tps`. The level preloads every asset a component parameter names, not only the Renderers’, and `LevelHost.material(id)` hands one back (ADR 0082).
- `tps` — **the third-person game the platform ships, as a package** (ADR 0065). Rigs + nametags (`createCharacterViews`), corpses (`createRagdoll`), the body dropping back in (`createAssembly`), the keyboard/mouse/touch bindings that keep the camera DOM-free (`createInputs`), the debug pane (`installDebugPane`), the body layers, and **`createAvatars`** — rigs, corpses and assemblies as one module, because a corpse suppresses an assembly, an assembly hides a rig and a death needs the pose the rig was last *drawn* in, so the order **is** the module. Every one of these was inside `@mp/game-client`, which made it the *platform’s* opinion that a game is a blocky humanoid over its own shoulder — and is why `ModeDescriptor` grew a knob per humanoid feature, there being no way to simply *import* it. **Nothing here reads a flag byte or a base index**: a caller says where a peer is and whether their dead bit is set. The line against `humanoid` is **math one side, pixels the other** — `humanoid` has no Three.js at all, which is why nine things import it cheaply including two headless tools. A game wanting something else takes none of this and needs no hook to say so. `setSelfVisible` is separate from `drawSelf` because the camera is placed *after* the bodies are drawn, and folding it in would hide the rig on last frame’s placement. Since ADR 0065 phase 3 it also owns **`startTpsClient(options)`** (`client.ts`, 803 lines) — the whole composition, built out of `@mp/game-client`’s services, and what all three shipped games’ `main.ts` calls. `TpsClientOptions` is an **argument list, not a contract**: `gait`, `animator`, `states` and `playerStates` live here rather than on `ModeDescriptor` precisely because only a client reads them. A game that outgrows it does not gain an option — it stops calling this and composes the services itself. `startTpsClient` **returns the keys** since ADR 0066: `scene`, `onFrame`, `partsOf`, `camera`, `world`, `level`, `id`. `onFrame` runs at the end of the frame so `partsOf` answers for it; `createFrameHooks` is separately tested because a hook removing itself mid-pass would silently skip the next one. `partsOf` is world-space (the first cut exposed joint-local `poseOf`, which cannot pin anything to a hand). `peers()` gives `{id, position, yaw, states}` per peer since ADR 0068, rebuilt once per frame from what the render pass computed so a game draws on the same interpolation instant the bodies were drawn at. `DebugPane` hands out its tweakpane root (ADR 0067) so a game adds its own folder of feel. The debug pane starts **collapsed, every folder included**, and carries an off-by-default `stats.js` frame meter driven by `DebugPane.frame()` from the render loop, measured after the game’s own hooks (ADR 0070). `ui` hands over the 2D overlay for a game’s HUD (ADR 0071) and `toScreen(world)` gives a world point in **overlay** pixels, or `null` behind the lens (ADR 0072). `debugFolders` picks which of the platform’s debug-pane folders a game gets; keyboard takes none (ADR 0075). `tuning` is the character’s live tuning, for a game that drives a value at runtime (ADR 0071 correction). The nametag is a `worldLabel` caller (ADR 0082). `meshesOf(node)` hands a game a level node’s drawn meshes to restyle (ADR 0082). `material(id)` returns a loaded material asset (ADR 0082). `excludeFromAO(object)` keeps a game’s object out of the AO prepass (ADR 0082).
- `camera` — the **third-person orbit camera** (ADR 0020/0055), extracted from parkour's composition root by ADR 0056: boom, zoom, occlusion, the see-through hole, the landing dip and the own-rig hide, driven by `update(dt, body, setOccluders)`. Takes a Three camera and nothing else it could not be tested without — **no DOM** (the host calls `lookMouse`/`lookTouch`/`zoomNotch`/`zoomPinch`) and **no physics import** (`observe(queries)` takes the two casts). `occlusion.ts` is the pure move-or-dither decision with its own tests; `CAMERA_TUNABLES` describes the knobs as data so the host builds the pane — including **`fov`** since ADR 0057, which was hardcoded at 60 in the stage where nothing could reach it, and is here because FOV is feel; the camera takes a `PerspectiveCamera` accordingly. Used by **both** the game and the editor’s play-test since ADR 0059; the editor had a third hand-written copy with no occlusion at all. `shot(eye)` puts the eye at an authored world position instead of on the boom (ADR 0060) — blended on the offset, orientation taken from it, occlusion no longer moving the camera but still holing what is in the way. Nothing drives it yet, on purpose.
- `render-pixi` — PixiJS 2D UI layer (ADR 0015): a transparent canvas stacked over Three, an overlay with pointer-lock-aware input, reusable widgets (panel/button/slider/list), and the **touch-control view** (`createTouchHud`, non-interactive by design — ADR 0022). Wired into the parkour pause screen.
- `mode` — **what a game contributes to the platform**, as one object (ADR 0052): a `ModeDescriptor` carrying its composed `registry`, character `tuning` and `standOffset`, a `gizmos` table mapping its rule components to marker colours, `spawn`, and `session` — the rules a tool runs (`effects`, `respawnAt`, `takeDeath`, `progress`). A game declares **no level settings**: there was a `config: ParamDecls` and a `modeParams` for them, and both went when their only user did — parkour's fall knobs were a rule in a setting's clothes (ADR 0053). **Headless**: gizmo colours are plain numbers and nothing mentions a scene, so a game's rules stay runnable by a bot. This is the seam that stopped the editor being implicitly parkour. `spawn.ts` is its only runtime code (ADR 0057): `spawnFrom(standOffset)` and `standingAt`, the marker lookup and golden-angle fan that parkour, swing and the template each had an identical copy of — with the stand-off a **parameter**, since a game whose character is a different size has its own, and taking only `Pick<LoadedLevel, 'markers'>` so it needs no physics world to test. → character, components, content, core `PlayerHost` + `playerDefs` are the seam that makes locomotion the game’s (ADR 0061): the host offers the character, the tuning and the platform poses, and the game closes over anything else itself — which is why `Ctx` never grew a field per capability. `actions.ts` maps a game’s key bindings to its action names, shared by both hosts. `gait` and `animator` are how a game says what its characters look like moving (ADR 0063): retune the shared cycle, or replace it with a factory that wraps it and overrides the pose for a state the platform never heard of. Nothing was added to `AnimationInput` for that — the factory is the game’s own code, so it closes over the game’s own state. `states` + `playerStates` declare which of a game’s own states have to reach other players (ADR 0064) — names in bit order, appending safe, reordering not. `PlayerHost` carries the **physics world and the level** since ADR 0066 (getters, so a component built before a respawn cannot capture a stale one) — which is why `@mp/physics` is a dependency, honest about a coupling `CharacterState.body` always had. The editor fills both from its play-test. `ModeSession.takeTeleport?` lets a rule relocate the player without killing them (ADR 0073).
- `i18n` — tiny dependency-free localization (ADR 0016): typed `t()`, 9 languages, browser-locale detect + runtime switch. Headless.
- `tools/netsim` — latency/jitter/loss transport wrapper. (Not wired into the current client — ADR 0013.)
- `tools/bots` — headless `colyseus.js` load clients + `load` harness; measures budgets 2 & 3 and doubles as the live integration check.
- `tools/viewer` — localhost content inspector (`pnpm dev:viewer`): picker, orbit, collider/marker/trigger overlays, jump-reachability gizmo, play-in-place. ADR 0014. Lists **level files** only — its per-piece catalogue went with the kit (ADR 0027).
- `tools/editor` — localhost level/prefab editor (`pnpm dev:editor`; ADR 0023 for what it authors, ADR 0024 for its UI). **Fixed-panel shell**: toolbar / Hierarchy | viewport | Inspector / Prefabs / status, one CSS grid with hand-rolled splitters (`splitter.ts`, ~40 lines, `clampSize` tested). `hierarchy.ts` is a real tree — rename in place (double-click), **drag to reorder or re-parent** (Unity's three-zone drop; cycles refused; world pose preserved), child instances shown by default and prefab pieces opened on demand (double-click a piece → open the shared definition with it selected); `rowsOf`/`zoneFor`/`dropTarget` are pure and tested. Gizmo has a **Local/Global** toggle; `projectPanel.ts` is the **Project browser** (tabs per asset kind with counts; **thumbnails for prefabs, models and materials** rendered once offscreen and cached via `previews.ts` + `render-three`'s `thumbnails.ts`, textures shown as themselves, sound audition, font sample; prefabs and models arm for placement, anything else opens in the Inspector), `assetInspector.ts` edits a material **generically from its shader's parameter list**, `assetImporter.ts` + the dev server's `/api/assets` and `/assets/<path>` routes assign ids and serve bytes (ADR 0026); `inspector.ts` is **our chrome around Tweakpane's widgets** (ADR 0038: a section per component, its header carrying the enable checkbox, a badge and a ⋯ menu with Remove / Move / Reset-or-Revert; one `Add Component` button; the override strip at the top; collapse state and scroll kept across the rebuild every enum change forces; a `when` on a declaration hides a parameter that is not relevant, so a component with a mode does not offer a field that mode ignores); `toolbar.ts` builds once and patches values. TransformControls gizmo with grid snap, mover end-position ghost, live re-instantiation as a validity check, and **play-in-place on the real `createLocalController` + `stepCharacter`**. Placing writes a **reference** into `Level.prefabs`; "Edit prefab" steps into the shared definition and every instance follows; "Extract to prefab" promotes an inline one-off. **Everything is a node with components** (ADR 0035): `editorDoc.ts` walks placement → what it inherits from its prefab → its own children, all one index space, and `kindOf` says `own` or `inherited` — ownership, not kind, since a piece and an instance are the same type now. `levelDoc` and `prefabDoc` are one implementation over `docOver` (a prefab is a level of one node; its root is protected from delete and duplicate, because it *is* the file). Component operations are `components`/`canAdd`/`addComponent`/`removeComponent`/`setParams`/`setComponentEnabled`; on an inherited node each of them writes a **`NodeOverride`** instead — params, enabled, added or removed — with `overridesOf`/`revert`/`applyToPrefab` behind Revert and Apply. `setTransform` replaced mutating what `transformOf` returned, since for an inherited node those are different objects. The **Inspector generates its own fields** from each component's declared parameters and offers an add-component picker filtered by `canAdd`, so a new component type needs no edit here; an overridden parameter is marked with a leading `•`. **Selection** is `selection.ts` (ADR 0031): a `number[]` with the primary **last**, so everything with one subject (Inspector, timeline, track helper) still reads a single index while transform/delete/duplicate/copy read the list. `modeFor` maps Ctrl→toggle and Shift→range; `rangeIn` runs over the panel's *visible* row order, not over indices; `rootsOf` drops a child selected alongside its parent, which is what makes delete and duplicate safe. Shift-range is Hierarchy-only — the viewport has no order to range over. **Keyboard** is `shortcuts.ts` (ADR 0030): bindings are a table of `{id, chords, label, run, enabled}`, matched on the **character** a key produces (`e.key`) with `e.code` only as a fallback for non-Latin layouts — so Ctrl+Z is the key marked Z on AZERTY, not the one where QWERTY puts Z. A disabled binding does not consume the key, which is what keeps WASD working during play. `history.ts` is **undo/redo by whole-document snapshot** (root document only; one entry per gizmo drag; no-op edits dropped by comparison; selection restored by sibling path), and `Doc.copy`/`Doc.paste` are the **clipboard**, which carries the prefab definitions a copied instance references so a paste is self-contained across files. **Animation** is the timeline strip in the bottom row, and it edits **one component's `keys` parameter** (ADR 0037): `Doc.keyEditors`/`keysOf`/`setKeys` address a `(node, componentId, param)` triple rather than "the selection's track", the strip is opened by **Edit keys** in that component's own Inspector section and names what it has open, and `loop`/`phase` live only in the component's section since they are declared parameters like any other. `trackEdit.ts` is every timeline mutation as a pure function, 16 of them with 55 tests (put a key or one channel, retime one channel with a **split** when the key holds both, shift a selection as a group, delete/copy/paste, easing, snapping, channel rows and segments, path points); `timeline.ts` is a **dope sheet** (ADR 0051): a lane per channel, a pixel time axis with wheel-zoom about the cursor and shift+wheel/middle-drag pan, box-select, multi-key drag, a typed row for the primary key, scrubbing on the ruler, and **Record mode** — armed, a gizmo drag writes a key at the playhead on the channel the gizmo mode moved. `writeKeys` is the single seam every key write goes through, so a drag can never write inline keys onto a node playing a clip; the clip's sibling parameter is named by the `keys` declaration (`KeysSpec.clip`) rather than assumed, so ADR 0037 still holds. Clips are editable in place, tagged in the toolbar, with Save as clip / Unlink and a 400ms debounce to disk — **not undoable**, since history snapshots the document and an asset is not in it, exactly as with a material. The viewport draws the **path** with a draggable handle per key. The gizmo writes **the selected key's offset when a key is selected, and the authored transform otherwise** — animated or not, since keys are offsets and the whole path rides the transform (ADR 0050 collapsed ADR 0029's third row, and with it the per-key delta rewrite and the drag snapshot it needed). `assetOptions(of)` feeds every asset-valued parameter from one accessor, and the Project panel's `+ new material` generalised to `onCreateAsset(kind, folder)` so an animation clip can be made empty there too; the library loads `*.anim.json` alongside materials and prefabs and satisfies `ClipSource`, so the viewport plays a clip a `Track` names. **The timeline opens a clip directly** since ADR 0051. Placement **overrides** are per node and per component (ADR 0035), structural ones included. **Right-click menus** are one module, `menu.ts` (ADR 0040): an item is `{label, run, enabled, why, hint, items}` — the same shape as a `shortcuts.ts` binding, so a command is described once and the menu shows its key. Submenus open on hover or ArrowRight; placement **flips** rather than clamps (`menuPlacement`/`submenuPlacement`, pure and tested) so the first item is never under the cursor; a refused operation stays greyed with a reason rather than vanishing. It serves the Hierarchy (row, and blank space), the Project panel — replacing a `prompt()` in which clearing the name deleted the file — the Inspector's `⋯`, the timeline's key menu, and the viewport, which opens on the pointer **release** because OrbitControls pans on right-drag. Three commands exist for it: `Doc.placeEmpty` (a grouping node, which nothing could make before), `focusSelection` (frames along the camera's current direction, also bound to `F`) and `pasteAt` (the group lands where you clicked, keeping its offsets). **Which game it is authoring for is explicit** (ADR 0052): `modes.ts` globs `modes/*/src/editorMode.ts`, a toolbar **game picker** sets the authoring context (narrowing the level list on `config.mode.name` and deciding what a new level is for), and a **Game row** beside Environment is where a level is reassigned — one dropdown, since a game declares no level settings (ADR 0053). Everything mode-shaped comes from the descriptor: the registry the document is validated and edited against, the rule gizmo colours, and play-in-place, which runs the game's own `session` rather than a copy of its rules. A level naming an uninstalled game still opens, with the row saying so. **Replacing the open document asks first** (`confirm.ts`): switching game, switching between Level and Prefab mode, and opening another file all go through one `guardUnsaved()`, which puts up a blocking Save / Discard / Cancel dialog when there are edits not on disk. Dirtiness is tracked at `recordEdit`, the seam every mutation already goes through, and cleared on save and on open — not from `history.canUndo()`, since undo depth survives a save. Save is awaitable so choosing it completes the write before the swap, and a failed write cancels the switch. The **game picker also opens that game's first level** now: it used to only filter the file list, so picking Swing showed swing's levels while parkour's `default` stayed open, and Save writes the *open* file — a save after switching wrote the wrong game's level. Harmless with one game installed, which is why it survived until there were two. Save syncs the file name to the document id — and, in prefab mode, to the root node's name. Reads/writes `content/` via a dev-server file API (which now returns `[{ name, mode }]` for levels, so a picker needs no per-file fetch). The palette greys out a prefab file whose components the open level’s game lacks, with the reason, and `placePrefab` refuses it (ADR 0076). A shared component a game lacks is **adopted into the game** on place, on Add Component, or on opening a level that uses it — `/api/games/<name>` read live, appended, document rebuilt (ADR 0077).
- `modes/_template` — **the game to copy** (ADR 0056): descriptor, minimal headless rules, a three-line `main.ts` documenting the six steps, and a working app shell. `_`-prefixed so the editor skips it; no level of its own, so it throws until one names it. It is the acceptance test for `@mp/game-client`: if that `main.ts` grows, something package-shaped leaked into a game. Since ADR 0065 its `main.ts` is the **file to read first when starting a game**: it calls `startTpsClient`, spreads the descriptor in, passes `gait`/`animator` as arguments, and documents what to do when the shipped game is not enough — stop calling it and compose `@mp/game-client`’s services, ~700 lines, with `packages/tps/src/client.ts` as the worked example.
- `modes/swing` — the second game (`pnpm dev:swing`), made by copying `_template` and pointing `content/levels/swing.json` at it. Controller, animation, camera, netcode and editor came for free. Registry takes the whole shared gameplay library because the level is a copy of parkour's; the session keeps no progress, so checkpoints and the goal are authorable and inert — the component is authoring, the rule is behaviour. `probe.ts` (ADR 0066) exercises five of the six new handles at runtime behind `?probe=1` — a cast, the node it hit, a line in the scene, redrawn per frame from the drawn hand. Not the rope; deletable. **Has a swing since ADR 0067**: `rope.ts` (the arithmetic, headless — one-sided damped spring, anchor scoring, the pump), `swing.ts` (the component that *is* this game’s locomotion, plus the shared `castForAnchor` fan), `ropeView.ts` (every rope on screen, per rendered frame), `peerRopes.ts` (other players’ anchors re-derived from one free flag bit, latched on the rising edge — ADR 0068). `content/levels/swing.json` carries a `swing test beams` group, one node, deletable.
- `modes/keyboard` — **the first real game** (`pnpm dev:keyboard`, port 5177), cloning Roblox’s `+1 Speed Keyboard Escape` (ADR 0069). `keycaps.ts` is the `Keyboard` component (**data on one node**: pitch, fill, height, glyphs, seed) plus the generator — one instanced mesh per letter pooled across the level, **no per-cap colliders or nodes**, and every cap under a character’s footprint **held down** until they leave. `keycapGeometry.ts` is the cap itself: taper, dished top, superellipse corners, legend on the top only via its own UVs, 84 triangles. The player is a **giant on a normal-sized keyboard** — 0.6 m caps against a 2 m character. Other players press keys too, with nothing on the wire. **No speed number, no click, no Wins yet**: this is the surface the game hangs off. **The loop works** (ADR 0071, corrected by ADR 0081): holding a direction on the ground earns **Experience** (`XP` on screen) by the step — four a second at any speed, keys pressing but paying nothing — Experience buys **Levels** on a ×1.15 curve, and a Level raises **Max Speed** (`10 + 2 × Level` studs/s) — three values, only one a speed, with the curve fitted to Kodjo’s own save and tested against it. `progression.ts` is the arithmetic, `hud.ts` the counter and Level bar, `popups.ts` the `+1` that floats off each struck key (ADR 0072). **Stages and Wins** (ADR 0073): a stage is whatever platforms end on a `WinsPad` (`wins.ts`); stand on it, bank `+N Wins`, teleport to spawn. No checkpoints, nothing locked. `rules.ts` turns the pad’s contact into the payout and the teleport. `groundMaxAccel: 150, airMaxAccel: 40` so a level-50 character carries momentum in the air and turns in arcs (ADR 0078). `gait: { inertiaAccelCap: 55, inertiaLateral: 0.35, maxStrideRate: 3.25 }` so a level-50 start does not throw the arms flat or the body sideways and the legs do not strobe (ADR 0079). A struck cap goes **fully** down before it may rise, however brief the step (`advancePress`, pure and tested); a key that only dipped for a one-frame footfall did not read as pressed. Presses **sweep** each character’s path since last frame, sampled no wider than the footprint (`sweepPoints`), because one sample per frame skipped keys once a frame’s travel exceeded 0.8 m — every frame under 40 fps at 32 m/s; a jump past `MAX_SWEEP` (4 m) is a teleport and presses nothing. Ground level is read off the **torso** less a rig constant, not the drawn feet: once the stride grew past `runSpeed` (ADR 0079) the IK-clamped legs floated the lower sole out of the 0.35 m band two frames in three at 32 m/s (measured), and presses came in bursts of four. **`Treadmill`** (`treadmill.ts`, ADR 0080): stand on it and earn steps at the same fixed cadence, each worth `perKey × multiplier`, a popup a step from the feet; no lock yet. **`Stepper`** (`steps.ts`, ADR 0081) is the player component that turns held input on the ground into the steps everything is paid in. The HUD shows the speed you run at (studs/s) right of the XP counter, and the Movement folder has a debug stand-in for the speed picker: `pick speed` on, `speed studs/s`, capped at Max Speed. **`StepPad`** (`stepPad.ts`, ADR 0082): step on it with the Wins it requires and every step pays its `perStep`; a `worldLabel` sign over each.
- `modes/parkour` — **six files** since ADR 0056: `main.ts` hands `PARKOUR_MODE` to `startTpsClient` (ADR 0065; it was `startGameClient`), `editorMode.ts` is the descriptor, `rules.ts` is its rules (headless), and three test files guard its rules, its levels and its asset references. Everything below this line moved to `@mp/game-client` and is described there; it is kept as the record of what the mode *contributes* rather than what it contains. Historically: the parkour mode on Colyseus rooms: Roblox-like controller (live-tunable), auto-join, nametags, data-driven levels, checkpoints/hazard/fall via physics triggers + persistence adapter, a **death ragdoll** + **spawn assembly** (one dynamic body per rig part, seeded from the animated pose; left click respawns and the body drops back in a pair at a time — ADR 0019; peers ragdoll and re-assemble too, each viewer running its own from one `STATE_DEAD` flag), a **Pixi pause screen** (settings + roster + restart, localized via `@mp/i18n`), and the **third-person camera** (wheel zoom, pitch to straight overhead, sphere-cast occlusion — ADR 0020 — with `cameraOcclusion.ts` deciding per frame whether an obstruction moves the camera or dithers away, ADR 0055). **Level selection** in `levels.ts`: `?level=<name>` loads `content/levels/<name>.json` (bundled via `import.meta.glob`), no param loads **`default.json`** (a placeholder so the game always boots; a file, so the editor can edit it — ADR 0027); an unknown name logs and falls back to it. The name is passed to `joinOrCreate` as a matchmaking filter. `assets.ts` builds the asset database from bundled `.meta` sidecars and preloads what a level references before the level view is built (ADR 0026); it also exports `CLIP_SOURCE`, the bundled animation clips as the `ClipSource` `instantiateLevel` takes (ADR 0050). `references.test.ts` is the **reference-integrity guard** (ADR 0028): every material/model id reachable from every shipped level resolves in `ASSET_DB`, every texture a material names resolves, and the seven greybox materials exist by name — a dangling id greyboxes silently, where an unknown `style` used to fall back harmlessly. Composition root; view pieces in `nametag.ts`/`characterView.ts`/`pauseMenu.ts`/`ragdoll.ts`/`assemble.ts`, collision layers in `layers.ts`.
- `content/levels` — level JSON **as node trees** (ADR 0035), loadable by name (`?level=<file>`):
  **`default.json`** (what loads with no param), `level1.json` (the ported original world), plus
  editor/Unity scratch files. `content/assets/prefabs/*.prefab.json` are root **nodes** for the same reason.

## Deferred (not built)

- **Mobile is playable but unmeasured and unvalidated on a device.** Touch controls exist and are wired
  (ADR 0022): stick bottom-left, jump bottom-right, look everywhere else, pinch to zoom, tap to respawn
  while dead. What has *not* happened is anyone playing it on a phone — so the layout numbers are first
  guesses (all exposed in the pane's **Touch** folder), and budgets 1 (frame time) and 5 (memory) are still
  unmeasured, which needs the same device session. The pause screen is the only UI laid out for a small
  screen; nothing else has been sized for one.
- **Nothing verifies a level is clearable.** `gym.test.ts` asserted every authored jump against the
  measured envelope; it and its subject are deleted (ADR 0027). The envelope is still measured
  (`packages/character/src/envelope*.test.ts`), so the numbers in `obstacles.md` hold — what is missing is a
  check over an authored level, which belongs in the editor as a reachability gizmo.
- **Parametric generators in the schema.** A prefab file stores baked pieces, so it cannot hold
  `padChain({ gap: 2.5 })` — only the boxes it produced. Considered and rejected when the generators were
  deleted (ADR 0027): shapes like a pad chain or an arc now have to be built piece by piece, since scaling
  cannot change a pad count or an arc radius.
- **Shared mutable component state (stage C5).** Components run (ADR 0036), and everything they can do is
  either pure or **local** — a rule that reacts to my contact and changes my character needs nobody else to
  agree, which is why every rule that exists cost nothing in netcode. What is *not* built is anything whose
  state every client must agree on: a door that stays open, a button, a pushable crate, a dynamic rigid body.
  That needs an owner and a sync channel — a netcode milestone, not a component, and explicitly Kodjo's call to
  open. `Ctx` gives no reach to do it, so the boundary is enforced by the API rather than by this paragraph.
- **No per-frame component hook.** Deliberate (ADR 0036): gameplay that reads frame time desyncs by
  construction. A render-step hook for purely cosmetic components is the obvious later addition, gated so it
  cannot touch the character.
- **No goal rule.** `Goal` is a component and `default.json` has a goal pad, but it carries no hook and nothing
  ends a run.
- **Other modes** (obby-tower variant, keyboard-run grind + progression), **glTF art layer**, **account-backed persistence** — accounted for by seams (ADR 0014), not built.
- **M9 — 2D path** (Rapier2d + Pixi-only). Deferred when scope narrowed to 3D.
- **Deploy** (Dockerfile + single-VPS) — re-scoped with Kodjo when a target exists. `infra/` empty.
