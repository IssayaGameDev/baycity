# Docs Index

System documentation for the multiplayer stack. Read this, then load only what
the current task needs.

Current state: **client-authoritative rooms on Colyseus (ADR 0011 + 0013), with a data-driven
content pipeline (ADR 0014).** Each client simulates its own entity and reports state; the
server (a Colyseus `Room`) relays peers, interpolated on a clock-synced timeline — no
`@colyseus/schema`. Product framing: an "extremely simplified Roblox" — a platform hosting a few
**modes** that share one stack. **Parkour** is the first mode (`modes/parkour`, `ParkourRoom`).

Content is **data** (`@mp/content`): levels are a tree of **nodes**, and a node holds a **list of
components** — `Collider`, `Mesh`, `Renderer`, `Track`, `Bumper`, `Checkpoint`, … — each a declared set of parameters
(ADR 0035, `PLAN-component-system.md`). `Piece` and `PrefabInstance` merged into one `Node`; the loader
reads the six engine components and hands a mode every component on the node that owns the collider you
touched, so adding a gameplay rule touches only its definition and the mode. Geometry is **authored data only** — the code kit and its generators are deleted (ADR 0027). Rendered
by a polished shared pipeline (`@mp/render-three`: IBL, ACES, soft shadows, GTAO/SMAA/bloom).
A gameplay rule is a **component on the node whose collider you touched**, detected by real engine contact. Inspect it locally
with the **viewer** (`tools/viewer`, `pnpm dev:viewer`); author it in the **editor** (`tools/editor`,
`pnpm dev:editor`, ADR 0023), which is the content path. The parkour mode **loads a level by name** —
`?level=<file>` from `content/levels/`, no param → **`default.json`**, a placeholder level so the game
always boots, editable in the editor like any other file (ADR 0027). The name also filters matchmaking,
so a room only holds clients on one level. Server stays content-free.

Wire is delta + quantized snapshots (v10: position + a state-flags byte — grounded/rising for animation, dead for the ragdoll — plus facing, locomotion-speed and movement-base bytes, none derivable from a position curve; while the base is set the transform is in that platform's frame — ADR 0021); budgets 2 & 3 validated with bots. Colyseus pinned to
**0.16** (matched client/server); default `ws` transport (uWS is a later swap); scale-out infra
(Redis/multi-region) deferred to deploy. History: server-authoritative through M10 (ADR 0011
reversed it); ball demo retired (tag `m10`); world/controller relocated out of `@mp/server/tps`
(ADR 0014). **M9 (2D path)** remains deferred (SEED §7).

## Built

- `core` — math (incl. quaternion helpers), entity model, fixed-timestep loop, `createSimClock` (fixed-step content time, slewed to a reference clock), transport interface.
- `net` — binary codecs (v10): snapshot (delta + quantized), welcome, state, ping/pong, roster; quantization utils (position, facing, speed). `NET_CHANNEL` is the Colyseus channel they ride.
- `physics` — Rapier3d wrapper: dynamic/fixed/kinematic bodies (position + rotation, linear + angular velocity), **kinematic character controller** (contact reporting + a downward `probeGround`), a general **sphere cast** (`castSphere`, with self-exclusion and on-demand query-index refresh), **collision layers** (`CollisionLayers`, applied to the controller's own queries too), headless + browser.
- `character` — the stack-level kinematic character controller (`stepCharacter`, `CharacterTuning`; ADR 0012), mode-agnostic. **Coyote time, a ceiling stop and a fall cap** (ADR 0034): the jump gate is `grounded || coyote > 0` off a countdown refilled with footing and spent on leaving, so a press just past a ledge still fires and one ledge is still one jump; `move`'s new `ceiling` flag ends the rise under a roof instead of leaving `vy` positive with nowhere to go; `maxFallSpeed` bounds the fall on a level with no kill plane. Relocated out of `@mp/server/tps`. **Platform carry** (movement base): rides a moving piece by keeping its position in that surface's frame (`PlatformPoseLookup`), and a jump off a mover inherits its velocity. `CharacterState.launch` is an upward speed something outside locomotion asks for and the step **consumes** (a bumper, ADR 0032): it joins `jumping` as `leaving`, which is what releases the ride, the footing and the movement base — a launch written onto `vy` from outside would be zeroed by the ride on the next tick. Paired with the loader's frozen posing — see `docs/physics.md`. Also the **blocky 11-part rig** (torso split at the waist) (`RIG`, proportions derived from the capsule) and its **procedural animator** (`createAnimator`): distance-driven stride, two-bone analytic IK, half-life smoothing. No skinning, no clips, no art; headless and unit-tested (ADR 0018).
- `content` — data-driven content. **The schema is nodes and components** (ADR 0035): `Node` = transform + `components: ComponentData[]` + `children` + an optional `prefab` reference with `overrides`; `NodeLevel` = a node forest plus a prefab table of root nodes. `nodes.ts` holds the six type names the engine itself reads (`COLLIDER`/`MESH`/`RENDERER`/`MATERIAL_OVERRIDE`/`TRACK`/`SPAWN`), the parameter readers, `effectiveNode` (a placement resolved against its prefab: overrides applied, the placement's own singletons beating the prefab's, its children appended after the inherited ones), `bakeOverrides` and `walkNodes`. `nodeValidate.ts` checks structure always and **parameters when handed a registry** — the capability seam that keeps this package from depending on `@mp/components`. `nodeLoader.ts` (`instantiateNodeLevel`) builds the world: a body and a mesh per enabled `Collider` (each at its own `center`), a `Renderer` that draws those colliders — or the `Mesh` beside it, if there is one —, `MaterialOverride` cascading down the subtree, `Track` driving the frame tree, `Spawn` as a marker — and `nodeOf(colliderHandle)` handing a mode the node's components so the loader never names a gameplay rule. The legacy `Piece`/`PrefabInstance` schema, `instantiateLegacyLevel` and `validateLevel` survive only as the migration's proof and are deleted once ADR 0035 is confirmed in a browser. Also the **prefab-reference helpers** (`resolvePrefab`/`effectivePieces`/`instancesOf`/`freeTableKey`/`walkInstances`; ADR 0023/0025), the **keyframe track evaluator** (`track.ts`, ADR 0029: `poseAt`/`trackTime`/`easeAt`/`trackDuration`, plus the `moveTrack`/`spinTrack` presets — pure, headless, 33 tests including a proof that the presets reproduce the deleted `move` behaviour term for term); the **loader** (`instantiateLevel`; `update(now, riddenCollider?)` poses the ridden piece without velocity and exposes `basePose` so riders can track it), `baseIndex`/`basePoseOf` expose clock-driven pieces as replicable movement bases (ADR 0021); and the **asset layer** (`assets.ts`, ADR 0026): kinds, `.meta` identity, `kindForPath`/`nameForPath`, the material schema (a shader name + tagged parameter values), and the visual-layer readers. A visual names a
  **material asset id** and nothing else — the `style` palette is gone (ADR 0028), and an unsurfaced primitive
  greyboxes. Headless, no rendering. ADR 0014.
- `components` — the component system's machinery and its built-in definitions (ADR 0035). `params.ts` is the **declaration layer**: nine parameter kinds (`number`/`bool`/`string`/`enum`/`vec3`/`asset`/`collider`/`keys`/`nodeRef`), `defaultsOf`, and `readParams` — which fills absent keys from the declaration, drops unknown ones, rejects a wrong type or a non-finite number with the parameter's path, and **validates collider shapes**, which nothing did before. `defineComponent` preserves the declaration through a `const` type parameter, so `params.loop` narrows to its own literal union. `registry.ts` is the lookup (throws on a duplicate type, hands out defaults, satisfies content's `ParamChecker` and `TypeInfo` structurally). `engine.ts` is what the loader reads — `Collider` (repeatable, with a `center`), `Mesh` and `Renderer` (Unity's split — ADR 0039), `MaterialOverride`, `Spawn` — and `gameplay.ts` is what a mode reads: `Checkpoint`, `Goal`, `Hazard`, `Bumper`, `Track`, all singletons, all **data-only** until stage C2 gives them hooks. `read.ts` is the typed accessor (`componentOn(components, Bumper)?.power` is a `number`). `runtime.ts` **runs** them (ADR 0036): `createComponentRuntime(loaded, registry, { character, effects })` builds one instance per hooked component in tree order and drives `attach`/`fixedUpdate`/`contact`/`detach`; `Ctx` offers the synced tick, a seeded `random()`, the local character's `launch` and two `Effects` (`kill`, `progress`), and withholds the wall clock, `Math.random`, the network and any other player — which is what lets a hook accumulate state without desyncing, and is the wall C5 has to move. `Self` carries typed `params`, mutable `state` from `init`, `get(def)` for another component on the same node and `find(ref)` for a `nodeRef`, resolved in this placement's own scope. `Bumper`, `Checkpoint` and `Hazard` own their reaction; `Track` and `Goal` deliberately have no hook. `legacy.ts` + `migrate.ts` + `fixtures/legacy-content.json` are the one-time migration and its equivalence proof; they go with the legacy schema.
- `server` — **Colyseus** `Server` (`startServer()`) hosting `ParkourRoom`: client-authoritative relay (per-client delta snapshots, no simulation, no schema), auto-join, roster/names, clock-sync ping/pong. Content-free.
- `client` — `colyseus.js` transport (`joinOrCreate`), interpolation, local authoritative controller (`localController`), clock sync, input abstraction (`.` headless + `./dom` adapters), and **touch controls** (`createTouchControls`: zone ownership by `pointerId`, re-centring stick, look/pinch/tap channels — headless and unit-tested; ADR 0022).
- `render-three` — WebGL2 stage (+ an explicit `resize()`, for a canvas sized by a panel layout rather than the window) + the polished greybox pipeline (IBL, ACES, soft shadows, GTAO/SMAA/bloom, level-view). `materials.ts` is down to `MARKER_COLORS`/`colorForMarker` (gizmo chrome) and `createGreyboxMaterial()` (the no-material surface) since ADR 0028; realizes `@mp/character`'s rig as nodes (`createCharacterRig`) and applies a `Pose`, or as loose unparented meshes for a ragdoll (`createLooseParts`); re-exports THREE + OrbitControls. **Shaders, assets + thumbnails** (ADR 0026): `shaders.ts` is a registry of shader definitions that each declare their own parameters and build a Three material (`standard` → `MeshStandardMaterial`, `unlit` → `MeshBasicMaterial`, `registerShader` for custom ones) plus `compileMaterial`; `assetRuntime.ts` is the **preload pass** (textures, glTF models, compiled materials, cached by id and cloned per use) that keeps `addLevel` synchronous; `thumbnails.ts` renders an asset preview offscreen (`fitDistance` is pure and tested).
- `render-pixi` — PixiJS 2D UI layer (ADR 0015): a transparent canvas stacked over Three, an overlay with pointer-lock-aware input, reusable widgets (panel/button/slider/list), and the **touch-control view** (`createTouchHud`, non-interactive by design — ADR 0022). Wired into the parkour pause screen.
- `i18n` — tiny dependency-free localization (ADR 0016): typed `t()`, 9 languages, browser-locale detect + runtime switch. Headless.
- `tools/netsim` — latency/jitter/loss transport wrapper. (Not wired into the current client — ADR 0013.)
- `tools/bots` — headless `colyseus.js` load clients + `load` harness; measures budgets 2 & 3 and doubles as the live integration check.
- `tools/viewer` — localhost content inspector (`pnpm dev:viewer`): picker, orbit, collider/marker/trigger overlays, jump-reachability gizmo, play-in-place. ADR 0014. Lists **level files** only — its per-piece catalogue went with the kit (ADR 0027).
- `tools/editor` — localhost level/prefab editor (`pnpm dev:editor`; ADR 0023 for what it authors, ADR 0024 for its UI). **Fixed-panel shell**: toolbar / Hierarchy | viewport | Inspector / Prefabs / status, one CSS grid with hand-rolled splitters (`splitter.ts`, ~40 lines, `clampSize` tested). `hierarchy.ts` is a real tree — rename in place (double-click), **drag to reorder or re-parent** (Unity's three-zone drop; cycles refused; world pose preserved), child instances shown by default and prefab pieces opened on demand (double-click a piece → open the shared definition with it selected); `rowsOf`/`zoneFor`/`dropTarget` are pure and tested. Gizmo has a **Local/Global** toggle; `projectPanel.ts` is the **Project browser** (tabs per asset kind with counts; **thumbnails for prefabs, models and materials** rendered once offscreen and cached via `previews.ts` + `render-three`'s `thumbnails.ts`, textures shown as themselves, sound audition, font sample; prefabs and models arm for placement, anything else opens in the Inspector), `assetInspector.ts` edits a material **generically from its shader's parameter list**, `assetImporter.ts` + the dev server's `/api/assets` and `/assets/<path>` routes assign ids and serve bytes (ADR 0026); `inspector.ts` is **our chrome around Tweakpane's widgets** (ADR 0038: a section per component, its header carrying the enable checkbox, a badge and a ⋯ menu with Remove / Move / Reset-or-Revert; one `Add Component` button; the override strip at the top; collapse state and scroll kept across the rebuild every enum change forces; a `when` on a declaration hides a parameter that is not relevant, so a component with a mode does not offer a field that mode ignores); `toolbar.ts` builds once and patches values. TransformControls gizmo with grid snap, mover end-position ghost, live re-instantiation as a validity check, and **play-in-place on the real `createLocalController` + `stepCharacter`**. Placing writes a **reference** into `Level.prefabs`; "Edit prefab" steps into the shared definition and every instance follows; "Extract to prefab" promotes an inline one-off. **Everything is a node with components** (ADR 0035): `editorDoc.ts` walks placement → what it inherits from its prefab → its own children, all one index space, and `kindOf` says `own` or `inherited` — ownership, not kind, since a piece and an instance are the same type now. `levelDoc` and `prefabDoc` are one implementation over `docOver` (a prefab is a level of one node; its root is protected from delete and duplicate, because it *is* the file). Component operations are `components`/`canAdd`/`addComponent`/`removeComponent`/`setParams`/`setComponentEnabled`; on an inherited node each of them writes a **`NodeOverride`** instead — params, enabled, added or removed — with `overridesOf`/`revert`/`applyToPrefab` behind Revert and Apply. `setTransform` replaced mutating what `transformOf` returned, since for an inherited node those are different objects. The **Inspector generates its own fields** from each component's declared parameters and offers an add-component picker filtered by `canAdd`, so a new component type needs no edit here; an overridden parameter is marked with a leading `•`. **Selection** is `selection.ts` (ADR 0031): a `number[]` with the primary **last**, so everything with one subject (Inspector, timeline, track helper) still reads a single index while transform/delete/duplicate/copy read the list. `modeFor` maps Ctrl→toggle and Shift→range; `rangeIn` runs over the panel's *visible* row order, not over indices; `rootsOf` drops a child selected alongside its parent, which is what makes delete and duplicate safe. Shift-range is Hierarchy-only — the viewport has no order to range over. **Keyboard** is `shortcuts.ts` (ADR 0030): bindings are a table of `{id, chords, label, run, enabled}`, matched on the **character** a key produces (`e.key`) with `e.code` only as a fallback for non-Latin layouts — so Ctrl+Z is the key marked Z on AZERTY, not the one where QWERTY puts Z. A disabled binding does not consume the key, which is what keeps WASD working during play. `history.ts` is **undo/redo by whole-document snapshot** (root document only; one entry per gizmo drag; no-op edits dropped by comparison; selection restored by sibling path), and `Doc.copy`/`Doc.paste` are the **clipboard**, which carries the prefab definitions a copied instance references so a paste is self-contained across files. **Animation** is the timeline strip in the bottom row, and it edits **one component's `keys` parameter** (ADR 0037): `Doc.keyEditors`/`keysOf`/`setKeys` address a `(node, componentId, param)` triple rather than "the selection's track", the strip is opened by **Edit keys** in that component's own Inspector section and names what it has open, and `loop`/`phase` live only in the component's section since they are declared parameters like any other. `trackEdit.ts` is every timeline mutation as a pure function (put/move/delete a key, segment easing, snapping, key rows, path points), `timeline.ts` draws the strip (ruler, diamonds, per-segment easing labels, a playhead that scrubs the whole level without entering Play), and the viewport draws the **path** with a draggable handle per key. The gizmo writes the authored transform when there is no track, the selected key when there is one, and offsets every key when a track is selected as a whole. Placement **overrides** are per node and per component (ADR 0035), structural ones included. **Right-click menus** are one module, `menu.ts` (ADR 0040): an item is `{label, run, enabled, why, hint, items}` — the same shape as a `shortcuts.ts` binding, so a command is described once and the menu shows its key. Submenus open on hover or ArrowRight; placement **flips** rather than clamps (`menuPlacement`/`submenuPlacement`, pure and tested) so the first item is never under the cursor; a refused operation stays greyed with a reason rather than vanishing. It serves the Hierarchy (row, and blank space), the Project panel — replacing a `prompt()` in which clearing the name deleted the file — the Inspector's `⋯`, the timeline's key menu, and the viewport, which opens on the pointer **release** because OrbitControls pans on right-drag. Three commands exist for it: `Doc.placeEmpty` (a grouping node, which nothing could make before), `focusSelection` (frames along the camera's current direction, also bound to `F`) and `pasteAt` (the group lands where you clicked, keeping its offsets). Save syncs the file name to the document id — and, in prefab mode, to the root node's name. Reads/writes `content/` via a dev-server file API.
- `modes/parkour` — the parkour mode on Colyseus rooms: Roblox-like controller (live-tunable), auto-join, nametags, data-driven levels, checkpoints/hazard/fall via physics triggers + persistence adapter, a **death ragdoll** + **spawn assembly** (one dynamic body per rig part, seeded from the animated pose; left click respawns and the body drops back in a pair at a time — ADR 0019; peers ragdoll and re-assemble too, each viewer running its own from one `STATE_DEAD` flag), a **Pixi pause screen** (settings + roster + restart, localized via `@mp/i18n`), and the **third-person camera** (wheel zoom, pitch to straight overhead, sphere-cast occlusion — ADR 0020). **Level selection** in `levels.ts`: `?level=<name>` loads `content/levels/<name>.json` (bundled via `import.meta.glob`), no param loads **`default.json`** (a placeholder so the game always boots; a file, so the editor can edit it — ADR 0027); an unknown name logs and falls back to it. The name is passed to `joinOrCreate` as a matchmaking filter. `assets.ts` builds the asset database from bundled `.meta` sidecars and preloads what a level references before the level view is built (ADR 0026). `references.test.ts` is the **reference-integrity guard** (ADR 0028): every material/model id reachable from every shipped level resolves in `ASSET_DB`, every texture a material names resolves, and the seven greybox materials exist by name — a dangling id greyboxes silently, where an unknown `style` used to fall back harmlessly. Composition root; view pieces in `nametag.ts`/`characterView.ts`/`pauseMenu.ts`/`ragdoll.ts`/`assemble.ts`, collision layers in `layers.ts`.
- `content/levels` — level JSON **as node trees** (ADR 0035), loadable by name (`?level=<file>`):
  **`default.json`** (what loads with no param), `level1.json` (the ported original world), plus
  editor/Unity scratch files. `content/assets/prefabs/*.prefab.json` are root **nodes** for the same reason.

## Deferred (not built)

- **Mobile is playable but unmeasured and unvalidated on a device.** Touch controls exist and are wired
  (ADR 0022): stick bottom-left, jump bottom-right, look everywhere else, pinch to zoom, tap to respawn
  while dead. What has *not* happened is anyone playing it on a phone — so the layout numbers are first
  guesses (all exposed in the pane's **Touch** folder), and budgets 1 (frame time) and 5 (memory) are still
  unmeasured, which needs the same device session. The pause screen is the only UI laid out for a small
  screen; nothing else has been sized for one.
- **Nothing verifies a level is clearable.** `gym.test.ts` asserted every authored jump against the
  measured envelope; it and its subject are deleted (ADR 0027). The envelope is still measured
  (`packages/character/src/envelope*.test.ts`), so the numbers in `obstacles.md` hold — what is missing is a
  check over an authored level, which belongs in the editor as a reachability gizmo.
- **Parametric generators in the schema.** A prefab file stores baked pieces, so it cannot hold
  `padChain({ gap: 2.5 })` — only the boxes it produced. Considered and rejected when the generators were
  deleted (ADR 0027): shapes like a pad chain or an arc now have to be built piece by piece, since scaling
  cannot change a pad count or an arc radius.
- **Shared mutable component state (stage C5).** Components run (ADR 0036), and everything they can do is
  either pure or **local** — a rule that reacts to my contact and changes my character needs nobody else to
  agree, which is why every rule that exists cost nothing in netcode. What is *not* built is anything whose
  state every client must agree on: a door that stays open, a button, a pushable crate, a dynamic rigid body.
  That needs an owner and a sync channel — a netcode milestone, not a component, and explicitly Kodjo's call to
  open. `Ctx` gives no reach to do it, so the boundary is enforced by the API rather than by this paragraph.
- **No per-frame component hook.** Deliberate (ADR 0036): gameplay that reads frame time desyncs by
  construction. A render-step hook for purely cosmetic components is the obvious later addition, gated so it
  cannot touch the character.
- **No goal rule.** `Goal` is a component and `default.json` has a goal pad, but it carries no hook and nothing
  ends a run.
- **Other modes** (obby-tower variant, keyboard-run grind + progression), **glTF art layer**, **account-backed persistence** — accounted for by seams (ADR 0014), not built.
- **M9 — 2D path** (Rapier2d + Pixi-only). Deferred when scope narrowed to 3D.
- **Deploy** (Dockerfile + single-VPS) — re-scoped with Kodjo when a target exists. `infra/` empty.

deleted once every part of it had been implemented and documented or explicitly superseded. Git has it.
