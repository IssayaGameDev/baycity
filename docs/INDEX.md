# Docs Index

System documentation for the multiplayer stack. Read this, then load only what
the current task needs.

Current state: **client-authoritative rooms on Colyseus (ADR 0011 + 0013), with a data-driven
content pipeline (ADR 0014).** Each client simulates its own entity and reports state; the
server (a Colyseus `Room`) relays peers, interpolated on a clock-synced timeline — no
`@colyseus/schema`. Product framing: an "extremely simplified Roblox" — a platform hosting a few
**modes** that share one stack. **Parkour** is the first game (`modes/parkour`), and what a game contributes to the platform is one `ModeDescriptor` (`@mp/mode`, ADR 0052). One `GameRoom` serves them all; which game a room is for is a matchmaking filter.

Content is **data** (`@mp/content`): levels are a tree of **nodes**, and a node holds a **list of
components** — `Collider`, `Mesh`, `Renderer`, `Light`, `Track`, `Bumper`, `Checkpoint`, … — each a declared set of parameters
(ADR 0035). `Piece` and `PrefabInstance` merged into one `Node`; the loader
reads the seven engine components and hands a mode every component on the node that owns the collider you
touched, so adding a gameplay rule touches only its definition and the mode. Geometry is **authored data only** — the code kit and its generators are deleted (ADR 0027). Rendered
by a polished shared pipeline (`@mp/render-three`: IBL, ACES, soft shadows, GTAO/SMAA/bloom).
A gameplay rule is a **component on the node whose collider you touched**, detected by real engine contact. Inspect it locally
with the **viewer** (`tools/viewer`, `pnpm dev:viewer`); author it in the **editor** (`tools/editor`,
`pnpm dev:editor`, ADR 0023), which is the content path. The parkour mode **loads a level by name** —
`?level=<file>` from `content/levels/`, no param → **`default.json`**, a placeholder level so the game
always boots, editable in the editor like any other file (ADR 0027). The name also filters matchmaking,
so a room only holds clients on one level. Server stays content-free.

Wire is delta + quantized snapshots (v10: position + a state-flags byte — grounded/rising for animation, dead for the ragdoll — plus facing, locomotion-speed and movement-base bytes, none derivable from a position curve; while the base is set the transform is in that platform's frame — ADR 0021); budgets 2 & 3 validated with bots. Colyseus pinned to
**0.16** (matched client/server); default `ws` transport (uWS is a later swap); scale-out infra
(Redis/multi-region) deferred to deploy. History: server-authoritative through M10 (ADR 0011
reversed it); ball demo retired (tag `m10`); world/controller relocated out of `@mp/server/tps`
(ADR 0014). **M9 (2D path)** remains deferred (SEED §7).

  - [0056](adr/0056-the-client-is-a-package.md) **the game client is a package, not a game's `main.ts`** (`@mp/camera` and `@mp/game-client`. ADR 0052 made a game one `ModeDescriptor` and that seam works, but it never covered the *client application*: `modes/parkour/src/main.ts` reached 1487 lines and almost none of it was parkour — stage and post-FX, asset preload, joining, interpolation, peer views, nametags, ragdoll and assembly, pause screen, debug pane, touch, the render loop and the whole camera. Nothing forced the split while there was one game; a second one makes every fix to that file a fix made twice. So: **a game owns its rules, its look and its level list, and the stack owns the client** — dependency law 3 applied to the thing that was exempt from it. `@mp/camera` is the first piece: ~300 lines of ADR 0020/0055 camera, with **no DOM** (the host owns pointer lock, wheel and touch and calls `lookMouse`/`zoomNotch`) and **no physics import** (`observe` takes the two casts, which is what lets the occlusion decision be tested against slabs on a number line). Its tunables are **data** — `CAMERA_TUNABLES` is `{key,label,min,max,step}` and the host builds the pane, so the package never depends on Tweakpane, a new parameter cannot ship without a slider, and a test checks every key against the defaults. Then `@mp/game-client`: `startGameClient(descriptor)` is the whole surface, and the descriptor is the whole of what varies — its registry validates and instantiates the level, its tuning drives the controller, its `session` is the rules, its `spawn` places arrivals, and its **name** picks both the level list and the save key. **`modes/parkour/src/main.ts` is 12 lines**, from 1487, and the mode is six files; its `package.json` went from 12 workspace deps to 8, so a game can no longer reach the netcode or the UI toolkit at all — the dependency law made structural rather than advisory. Two seams had to change because they only made sense for one game: `ModeDescriptor.spawn` takes an optional `seed` (a client spreads arrivals round one marker, a tool places one body — one function, not two), and `localParkourPersistence` became `localProgress(mode)` keyed by game name, since two games sharing `parkour.state` would let a checkpoint in one resume a run in the other. Level and asset bundling moved too: `import.meta.glob` resolves relative to the file and a package's `src` sits at the same depth as a mode's, so the globs find exactly what they found before. `client.ts` is 1239 lines in one function — **moved, not redesigned**, taken knowingly, with decomposition as the follow-up now that callers only see the entry point. Rejected: folding it into `@mp/client`, which is headless-capable so bots can use it; and copying `main.ts` for game two and extracting later, since the churn is concentrated in exactly the part that is not game-specific)
  - [0055](adr/0055-see-through-obstructions.md) **an obstruction dithers away instead of shoving the camera** (amends ADR 0020. Kodjo asked for the occluder to go locally invisible rather than the camera zooming in. It can, but the pull-in was doing **two** jobs — keeping the character visible, and keeping the camera out of places it has no business being — and every problem in this ADR came from forgetting the second. **One rule**: the obstruction is holed and the camera keeps its distance, unless the camera would sit *inside solid* (the near plane in geometry, looking at the level's backfaces) or *below the character's feet* (where a hole is a view of the level's underside); either way it stops where the sweep cleared, exactly as ADR 0020 made it stop. "Inside solid" needs `sphereOverlaps`, a **new** physics query, because `castSphere` deliberately ignores an overlap it is *leaving*, so from inside a wall it reports clear air. "Below the feet" is a test on the **camera's** height, not the surface's — nothing in a level says which collider is the ground and nothing should, since the ground *is* a platform. The decision lives in `modes/parkour/src/cameraOcclusion.ts`, pure with the queries injected, so it is tested against slabs on a number line. **Three sightlines, not one**: the camera aims level with the top of the head, so a platform can lie across the whole body with the head clear above it — two extra probes down the capsule's spine catch it, which is what most third-person cameras do and cheaper than frustum-corner casts (Roblox's Popper), whose fan spreads *away* from the character and still misses a narrow beam between the rays. **Only the meshes a cast names wear the hole** (`levelView.setOccluders`, via the new `VisualItem.colliderHandles`), each getting a masked **copy** of its material — materials are cached by asset id and shared, so patching in place would fade the whole level. That copy-per-occluder is the third design; the two before it tried to keep the hole off the floor from inside the shader and both shipped artifacts, because **no test on a fragment's position can separate the platform overhead from the floor beside the character's feet** — from a high camera the floor is both nearer to the eye and right beside the sight line. The hole is a **cone** (constant angle, so constant size on screen at any zoom) centred on the capsule's middle rather than the aim point, **dithered** with interleaved gradient noise rather than alpha (opaque, no sorting; not Bayer, since Three compiles GLSL ES 1.00 which forbids dynamic array indexing), and animated by **growing the radius** rather than the strength, so the interior is cut from the first frame and stipple only ever lives in the moving rim. **AO had to be told and shadows had to be left alone**: GTAO reads its own depth prepass, which never saw the discard, so the character came out wearing occlusion cast by a platform the player cannot see — `PostFXOptions.aoIgnores` hides the occluders for that one pass. Shadows stay: a surface whose pixels are gone still shades the level, and a hole in a shadow is not a thing. Two diagnostic checkboxes (`sun shadows`, `ambient occl.`) earned their place immediately — the artifact that survived four fixes was AO, and one toggle proved it in seconds. Known open: frame-edge clipping (ADR 0020's, still), the dither swimming with camera motion, and the camera still able to sit in a neighbouring interior. Every dead end is written down — the plane cut that made a half circle, the depth slab that made a band on oblique surfaces, the thickness allowance that flip-flopped as the camera orbited, the footing-collider rule that collapsed the camera into the head, the pitch clamp that froze the orbit, the hit-height test that was unreachable, and the shadow-map hole that cast a beam from the sun)
  - [0054](adr/0054-trigger-colliders.md) **a collider can be a trigger** (completes ADR 0053, which needed this and did not have it: with only a solid mode, the kill plane was a *floor* — you land on the thing meant to be empty space with a rule in it. `Collider.trigger`, default off, passed through as `BodyOptions.sensor` → `ColliderDesc.setSensor`. Still a collider on the node and still in `colliderHandles`, so a rule beside it fires as before; only the physical response goes. **Detection has to be a second pass**: a sensor resolves no movement, so it never reaches `CharacterBody.collisions`, which is the record of what the capsule pushed against. Hence `CharacterBody.overlaps()` — an explicit `intersectionsWithShape` with `EXCLUDE_SOLIDS`, not narrow-phase pairs, because it needs no `step()` since the capsule moved and returns sensors *only*, so the two lists are disjoint and a host concatenates them. **Three query paths had to learn to ignore sensors and one was a real bug**, caught by the test rather than assumed: Rapier's `computeColliderMovement` resolves against sensors unless told otherwise, so without `EXCLUDE_SENSORS` a sensor wall stopped the capsule exactly like a solid one. The other two would have been silent — `probeGround` would have made a trigger into footing, and `castSphere` would have pulled the camera boom in for a volume you can walk through. Nine tests across physics and the loader, one per path that can silently regress, plus a content guard per level that its plane stays a trigger)

He is right — "falling past this height kills you" is a **rule**, and every other rule here is a component reached by real engine contact. What was wrong: one row for two channels, so a key holding both was one diamond with no way to grab half of it; the whole track always filling the width in CSS percentages, so no zoom and no pan; one selected key ever, so retiming six keys was six drags; nothing typeable; and the strip destroyed and rebuilt per pointer event, which is why the playhead needed an escape hatch and the drag listeners had to live on `window`.   - [0043](adr/0043-air-control-matches-roblox.md) **air control equals ground control, as Roblox's does** (`airControl` 1: Roblox uses `TurnSpeedFactor` 1 in both its ground and air controllers, so it does not restrict air steering at all; stopping drops from 0.40 s to 0.17 s, and run-up stops being worth anything — the standing gap now beats the running one)
  - [0042](adr/0042-fast-vertical-platforms.md) **fast vertical platforms: footing is not just a downward ray** (rising away from a surface is not standing on it; the base can come from the controller's contacts when the probe's centre ray cannot reach; the probe may look as far as the base actually moved; `jumpCutScale` off)
  - [0041](adr/0041-jump-feel.md) **jump feel: an exact arc, a shaped one, and two forgivenesses** (the vertical step is the trapezoid, so `jumpHeight` means the apex; latched presses + a jump buffer; lift momentum storage; fall bias / apex float / release-cut live at the literature's values, which widened the measured gap to 4.1 m; corner correction measured as unnecessary for a capsule)
  - [0034](adr/0034-coyote-time.md) **coyote time, plus the two vertical stops the jump was missing** (a roof ends the rise off contact normals; `maxFallSpeed` caps the fall; the grace is spent on the way out so one ledge is one jump)
  - [0033](adr/0033-piece-objects-and-prefab-overrides.md) **a piece is an object the document addresses; a placement overrides it** (one twist, everything shut; overrides keyed by a minted piece id; `effectivePieces` shared by loader and editor)
  - [0032](adr/0032-bumper.md) **a bumper/trampoline, and triggers that carry parameters** (`Trigger` is a union; the launch goes through `stepCharacter` so it escapes a ride; nothing on the wire)
  - [0031](adr/0031-multi-selection.md) **multi-selection with a primary** (Ctrl toggles, Shift ranges over the *visible* rows; structural ops act on roots bottom-up; the gizmo mirrors the primary's delta)
  - [0030](adr/0030-keyboard-shortcuts.md) **shortcuts match the character, not the key position** (QWERTY/AZERTY/Dvorak; a binding table as data), plus **undo/redo by snapshot** and a prefab-carrying **clipboard**
  - [0029](adr/0029-keyframe-tracks.md) **motion is a keyframe track, edited on a timeline** (`move`/`rotate` deleted to presets; `phaseMs` ends the lockstep; path handles in the viewport; no graph editor, deliberately)
  - [0028](adr/0028-materials-replace-styles.md) **`style` is deleted; a material asset is the one visual answer** (the greybox palette ships as 7 material assets; the override moved to `PrefabInstance.material`; a reference-integrity test)
  - [0027](adr/0027-content-is-data-only.md) **geometry is authored data**: the code kit + generators deleted, the gym with them, a `default.json` level file in their place
  - [0026](adr/0026-asset-pipeline.md) **assets referenced by id in a `.meta` sidecar; a material is a shader instance** (textures/models/materials/shaders/sounds/fonts; preload pass; generic material inspector)
  - [0025](adr/0025-nested-placement.md) **instances nest to any depth**; the loader composes a frame tree (compound motion; no wire change)
  - [0024](adr/0024-editor-ui-shell.md) **the editor's UI is a fixed-panel DOM shell** (CSS-grid layout, hand-rolled splitters, hierarchy panel; Tweakpane confined to the Inspector)
  - [0023](adr/0023-authoring-content.md) **content is authored in the in-browser editor** (prefab references + instance overrides; Unity retired to assets, its conversion facts preserved)

## Built

- `core` — math (incl. quaternion helpers), entity model, fixed-timestep loop, `createSimClock` (fixed-step content time, slewed to a reference clock), transport interface.
- `net` — binary codecs (v10): snapshot (delta + quantized), welcome, state, ping/pong, roster; quantization utils (position, facing, speed). `NET_CHANNEL` is the Colyseus channel they ride.
- `physics` — Rapier3d wrapper: dynamic/fixed/kinematic bodies (position + rotation, linear + angular velocity), **kinematic character controller** (contact reporting + a downward `probeGround`), a general **sphere cast** (`castSphere`, with self-exclusion and on-demand query-index refresh), a **sphere overlap** (`sphereOverlaps` — "is this spot free", which a cast cannot answer since `castSphere` ignores an overlap it is leaving; ADR 0055), **collision layers** (`CollisionLayers`, applied to the controller's own queries too), and **triggers** (`BodyOptions.sensor`, ADR 0054: detected on overlap, resolving nothing — so `EXCLUDE_SENSORS` on the controller's move, on `probeGround` and on `castSphere`, and a separate `CharacterBody.overlaps()` shape query with `EXCLUDE_SOLIDS` to find them, since a sensor by definition never reaches `collisions`). Headless + browser.
- `character` — the stack-level kinematic character controller (`stepCharacter`, `CharacterTuning`; ADR 0012), mode-agnostic. **Jump feel** (ADR 0034/0035): the vertical step is the exact trapezoid `½(v₀+v₁)·dt` — except while settling on a surface, where the full `v·dt` is the contact nudge and making it "exact" destabilises the controller's horizontal resolve — so `jumpHeight` is the measured apex to 0.2%; `jumpBuffer` mirrors `coyote` (early presses and one-tick taps both survive); `liftVel`/`liftStore` hand a departed mover's velocity to a late jump; `fallGravityScale` 1.6 / `apexGravityScale` 0.5 / `jumpCutScale` 0.4 shape the arc (each reverts to 1), and the apex float is gated on having no ground underfoot because a resting character sits at `vy = 0` inside any apex window. Earlier: the jump gate is `grounded || coyote > 0` off a countdown refilled with footing and spent on leaving, so a press just past a ledge still fires and one ledge is still one jump; `move`'s new `ceiling` flag ends the rise under a roof instead of leaving `vy` positive with nowhere to go; `maxFallSpeed` bounds the fall on a level with no kill plane. Relocated out of `@mp/server/tps`. **Platform carry** (movement base): rides a moving piece by keeping its position in that surface's frame (`PlatformPoseLookup`), and a jump off a mover inherits its velocity. `CharacterState.launch` is an upward speed something outside locomotion asks for and the step **consumes** (a bumper, ADR 0032): it joins `jumping` as `leaving`, which is what releases the ride, the footing and the movement base — a launch written onto `vy` from outside would be zeroed by the ride on the next tick. Paired with the loader's frozen posing — see `docs/physics.md`. Also the **blocky 11-part rig** (torso split at the waist) (`RIG`, proportions derived from the capsule) and its **procedural animator** (`createAnimator`): distance-driven stride, two-bone analytic IK, half-life smoothing. No skinning, no clips, no art; headless and unit-tested (ADR 0018).
- `content` — data-driven content. **The schema is nodes and components** (ADR 0035): `Node` = transform + `components: ComponentData[]` + `children` + an optional `prefab` reference with `overrides`; `Level` = a node forest plus a prefab table of root nodes. `nodes.ts` holds the six type names the engine itself reads (`COLLIDER`/`MESH`/`RENDERER`/`MATERIAL_OVERRIDE`/`TRACK`/`SPAWN`), the parameter readers, `effectiveNode` (a placement resolved against its prefab: overrides applied, the placement's own singletons beating the prefab's, its children appended after the inherited ones), `bakeOverrides` and `walkNodes`. `validate.ts` checks structure always and **parameters when handed a registry** (`ParamChecker`) — the capability seam that keeps this package from depending on `@mp/components`. `loader.ts` (`instantiateLevel`) builds the world: a body and a mesh per enabled `Collider` (each at its own `center`), a `Renderer` that draws those colliders — or the `Mesh` beside it, if there is one — `MaterialOverride` cascading down the subtree, `Track` driving the frame tree, `Spawn` as a marker, and `nodeOf(colliderHandle)`/`findNode` handing a mode the node's components so the loader never names a gameplay rule. Also `freeTableKey` (a prefab table's dedupe rule) and the **keyframe track evaluator** (`track.ts`, ADR 0029: `poseAt`/`trackTime`/`easeAt`/`trackDuration`, plus the `moveTrack`/`spinTrack` presets — pure, headless, 36 tests including a proof that the presets reproduce the deleted `move` behaviour term for term. **A key is an offset from the node's transform, not a pose that replaces it** — ADR 0050: `poseAt` adds the sampled key per channel, a zero key is the rest pose, and a channel with no keys returns the authored value untouched rather than adding zero to it. That is what lets a mover be duplicated or reparented and what makes a track shareable; the presets take no base pose because of it. `Track` may name an animation asset instead of carrying keys, resolved by `keysOf` through the optional **`ClipSource`** capability `instantiateLevel` takes alongside `TypeInfo` — inline keys win, a missing clip stands still); the loader's clock (`update(now, riddenCollider?)` poses the ridden node without velocity and exposes `basePose` so riders can track it; `baseIndex`/`basePoseOf` expose clock-driven nodes as replicable movement bases — ADR 0021); and the **asset layer** (`assets.ts`, ADR 0026): kinds, `.meta` identity,
  `kindForPath`/`nameForPath`, the material schema (a shader name + tagged parameter values) and the
  **animation schema** (`AnimationAsset`/`isAnimationAsset`, `*.anim.json`, holding `keys` only — ADR 0050).
  A `Renderer` names a **material asset id** and nothing else — the `style` palette is gone (ADR 0028), and an
  unsurfaced node greyboxes. Headless, no rendering. ADR 0014.
- `components` — the component system's machinery and its built-in definitions (ADR 0035). `params.ts` is the **declaration layer**: nine parameter kinds (`number`/`bool`/`string`/`enum`/`vec3`/`asset`/`collider`/`keys`/`nodeRef`), `defaultsOf`, and `readParams` — which fills absent keys from the declaration, drops unknown ones, rejects a wrong type or a non-finite number with the parameter's path, and **validates collider shapes**, which nothing did before. `defineComponent` preserves the declaration through a `const` type parameter, so `params.loop` narrows to its own literal union. `registry.ts` is the lookup (throws on a duplicate type, hands out defaults, satisfies content's `ParamChecker` and `TypeInfo` structurally); `createRegistry` is how a **game composes its own set** (ADR 0052), and `DEFAULT_REGISTRY` is no longer what a game runs on — it is engine plus the whole shared library, kept as the fallback for a level naming an uninstalled game and as a default for tests. `engine.ts` is what the loader reads — `Collider` (repeatable, with a `center` and a `trigger` flag that makes it a sensor — ADR 0054), `Mesh` and `Renderer` (Unity's split — ADR 0039), `MaterialOverride`, `Spawn` — and `gameplay.ts` is the **shared gameplay library** a game picks from: `Checkpoint`, `Goal`, `Hazard`, `Bumper`, `Track` (whose motion is either its inline `keys` or the animation asset its `clip` names — ADR 0050), all singletons. Shared rather than parkour's (ADR 0052): several games want checkpoints and goals, so what changed was that a game **opts in** through its own registry instead of inheriting all of them. `read.ts` is the typed accessor (`componentOn(components, Bumper)?.power` is a `number`). `runtime.ts` **runs** them (ADR 0036): `createComponentRuntime(loaded, registry, { character, effects })` builds one instance per hooked component in tree order and drives `attach`/`fixedUpdate`/`contact`/`detach`; `Ctx` offers the synced tick, a seeded `random()`, the local character's `launch` and two `Effects` (`kill`, `progress`), and withholds the wall clock, `Math.random`, the network and any other player — which is what lets a hook accumulate state without desyncing, and is the wall C5 has to move. `Self` carries typed `params`, mutable `state` from `init`, `get(def)` for another component on the same node and `find(ref)` for a `nodeRef`, resolved in this placement's own scope. `Bumper`, `Checkpoint` and `Hazard` own their reaction; `Track` and `Goal` deliberately have no hook.
- `server` — **Colyseus** `Server` (`startServer()`) hosting one `GameRoom` for every game, matched by `filterBy(['game', 'level'])` (ADR 0052 — nothing in the room is any game, so which one it is is a filter and not a subclass): client-authoritative relay (per-client delta snapshots, no simulation, no schema), auto-join, roster/names, clock-sync ping/pong. Content-free.
- `client` — `colyseus.js` transport (`joinOrCreate`), interpolation, local authoritative controller (`localController`), clock sync, input abstraction (`.` headless + `./dom` adapters), and **touch controls** (`createTouchControls`: zone ownership by `pointerId`, re-centring stick, look/pinch/tap channels — headless and unit-tested; ADR 0022).
- `render-three` — WebGL2 stage (+ an explicit `resize()`, for a canvas sized by a panel layout rather than the window) + the polished greybox pipeline (IBL, ACES, soft shadows, GTAO/SMAA/bloom, level-view). `environment.ts` owns **the sun**, and it is one input (ADR 0046): `sunElevation`/`sunAzimuth` drive the key light, its shadow frustum, the sky bake and the environment map, with a mutable `sunAngles`/`skyParams` pair and a `refresh()` shaped for a Tweakpane binding. `environment.ts` reads `LevelConfig.environment` via `applyEnvironment` (ADR 0048) — sun, ambient and sky in one block — so nothing about how a level is lit is a constant. `lights.ts` realizes a level's **content lights** (including the `hemisphere` fill, which is a node now) (ADR 0047: `createLight`/`addLights`, shadow casters capped at 4 because a caster is an extra scene render and a point light is six; the sun is not one of these). `sky.ts` is the **sky**: a hand-written gradient shader (monotonic `mix` over `pow` of height, plus a sun glow and disc) baked to a 512-per-face half-float cubemap that serves as both `scene.background` and the PMREM source, with `sunDirection` and `skyUniformValues` pure and tested. Lighting is dialled to `environmentIntensity` 0.2 against a white-over-grey `HemisphereLight` at 0.4, because a saturated sky lights blue 21x red. `installSky`/`loadSky` still load an equirect texture, kept only as the backdrop toggle the procedural sky is judged against (ADR 0045). `materials.ts` is down to `MARKER_COLORS`/`colorForMarker` (gizmo chrome), `createGreyboxMaterial()` (the no-material surface) since ADR 0028, and **the bevel** (ADR 0044: `BEVEL_RADIUS`/`BEVEL_SEGMENTS`/`bevelFor` and the `geometryForCollider` vs `outlineGeometryForCollider` split — the drawn box is a rounded cuboid, the outlined one is sharp); realizes `@mp/character`'s rig as nodes (`createCharacterRig`) and applies a `Pose`, or as loose unparented meshes for a ragdoll (`createLooseParts`); re-exports THREE + OrbitControls. **Shaders, assets + thumbnails** (ADR 0026): `shaders.ts` is a registry of shader definitions that each declare their own parameters and build a Three material (`standard` → `MeshStandardMaterial`, `unlit` → `MeshBasicMaterial`, `registerShader` for custom ones) plus `compileMaterial`; `assetRuntime.ts` is the **preload pass** (textures, glTF models, compiled materials, cached by id and cloned per use) that keeps `addLevel` synchronous; `thumbnails.ts` renders an asset preview offscreen (`fitDistance` is pure and tested). `cutout.ts` is the **see-through hole** (ADR 0055): a `CutoutMask` handed to `addLevel` dithers a cone from the eye to the character, so what is in the way vanishes instead of the camera moving. `setOccluders(handles)` swaps a masked **copy** of its material onto each mesh a cast reports (found through the new `VisualItem.colliderHandles`) and puts the plain one back after — a copy because materials are shared by every piece using them, and only some are in the way. One `onBeforeCompile` across every copy, so they share a compiled program, and one shared set of uniforms driving all of them. Opt-in per view, so the editor and viewer never copy a material at all. `postfx.ts` gained `aoIgnores`, because GTAO reads its own depth prepass and never saw the discard: the character came out wearing occlusion cast by a platform that was not being drawn, so two tiny passes bracket the AO pass and hide the occluders for it. Shadows are deliberately left alone. `cutoutCoverage` is the tested copy of the geometry the GLSL transcribes; `injectCutout` is the string edit, checked against `THREE.ShaderLib` itself.
- `game-client` — **the client every game runs** (ADR 0056): `startGameClient(descriptor)` and nothing else in its surface. Owns the scene, post-FX, level and asset bundling (`levelsFor(mode, registry)`, filtered by `config.mode.name`), joining, interpolation, peer views, nametags, ragdoll + assembly, pause screen, debug pane, touch, camera and render loop. `localProgress(mode)` keys saves by game so two games cannot share one. `client.ts` is 870 lines after the first decomposition pass; `pane.ts` (every live tunable, pure wiring), `inputs.ts` (keyboard/pointer lock/wheel/touch — what keeps the camera DOM-free), `scene.ts` (stage, pipeline, sky, post-FX, nametag render step) and `status.ts` (the status line and the locale, together because the line is key-driven) came out. What is left is the stateful core: netcode, local sim, render loop.
- `camera` — the **third-person orbit camera** (ADR 0020/0055), extracted from parkour's composition root by ADR 0056: boom, zoom, occlusion, the see-through hole, the landing dip and the own-rig hide, driven by `update(dt, body, setOccluders)`. Takes a Three camera and nothing else it could not be tested without — **no DOM** (the host calls `lookMouse`/`lookTouch`/`zoomNotch`/`zoomPinch`) and **no physics import** (`observe(queries)` takes the two casts). `occlusion.ts` is the pure move-or-dither decision with its own tests; `CAMERA_TUNABLES` describes the knobs as data so the host builds the pane.
- `render-pixi` — PixiJS 2D UI layer (ADR 0015): a transparent canvas stacked over Three, an overlay with pointer-lock-aware input, reusable widgets (panel/button/slider/list), and the **touch-control view** (`createTouchHud`, non-interactive by design — ADR 0022). Wired into the parkour pause screen.
- `mode` — **what a game contributes to the platform**, as one object (ADR 0052): a `ModeDescriptor` carrying its composed `registry`, character `tuning` and `standOffset`, a `gizmos` table mapping its rule components to marker colours, `spawn`, and `session` — the rules a tool runs (`effects`, `respawnAt`, `takeDeath`, `progress`). A game declares **no level settings**: there was a `config: ParamDecls` and a `modeParams` for them, and both went when their only user did — parkour's fall knobs were a rule in a setting's clothes (ADR 0053). **Headless**: gizmo colours are plain numbers and nothing mentions a scene, so a game's rules stay runnable by a bot. This is the seam that stopped the editor being implicitly parkour. → character, components, content, core
- `i18n` — tiny dependency-free localization (ADR 0016): typed `t()`, 9 languages, browser-locale detect + runtime switch. Headless.
- `tools/netsim` — latency/jitter/loss transport wrapper. (Not wired into the current client — ADR 0013.)
- `tools/bots` — headless `colyseus.js` load clients + `load` harness; measures budgets 2 & 3 and doubles as the live integration check.
- `tools/viewer` — localhost content inspector (`pnpm dev:viewer`): picker, orbit, collider/marker/trigger overlays, jump-reachability gizmo, play-in-place. ADR 0014. Lists **level files** only — its per-piece catalogue went with the kit (ADR 0027).
- `tools/editor` — localhost level/prefab editor (`pnpm dev:editor`; ADR 0023 for what it authors, ADR 0024 for its UI). **Fixed-panel shell**: toolbar / Hierarchy | viewport | Inspector / Prefabs / status, one CSS grid with hand-rolled splitters (`splitter.ts`, ~40 lines, `clampSize` tested). `hierarchy.ts` is a real tree — rename in place (double-click), **drag to reorder or re-parent** (Unity's three-zone drop; cycles refused; world pose preserved), child instances shown by default and prefab pieces opened on demand (double-click a piece → open the shared definition with it selected); `rowsOf`/`zoneFor`/`dropTarget` are pure and tested. Gizmo has a **Local/Global** toggle; `projectPanel.ts` is the **Project browser** (tabs per asset kind with counts; **thumbnails for prefabs, models and materials** rendered once offscreen and cached via `previews.ts` + `render-three`'s `thumbnails.ts`, textures shown as themselves, sound audition, font sample; prefabs and models arm for placement, anything else opens in the Inspector), `assetInspector.ts` edits a material **generically from its shader's parameter list**, `assetImporter.ts` + the dev server's `/api/assets` and `/assets/<path>` routes assign ids and serve bytes (ADR 0026); `inspector.ts` is **our chrome around Tweakpane's widgets** (ADR 0038: a section per component, its header carrying the enable checkbox, a badge and a ⋯ menu with Remove / Move / Reset-or-Revert; one `Add Component` button; the override strip at the top; collapse state and scroll kept across the rebuild every enum change forces; a `when` on a declaration hides a parameter that is not relevant, so a component with a mode does not offer a field that mode ignores); `toolbar.ts` builds once and patches values. TransformControls gizmo with grid snap, mover end-position ghost, live re-instantiation as a validity check, and **play-in-place on the real `createLocalController` + `stepCharacter`**. Placing writes a **reference** into `Level.prefabs`; "Edit prefab" steps into the shared definition and every instance follows; "Extract to prefab" promotes an inline one-off. **Everything is a node with components** (ADR 0035): `editorDoc.ts` walks placement → what it inherits from its prefab → its own children, all one index space, and `kindOf` says `own` or `inherited` — ownership, not kind, since a piece and an instance are the same type now. `levelDoc` and `prefabDoc` are one implementation over `docOver` (a prefab is a level of one node; its root is protected from delete and duplicate, because it *is* the file). Component operations are `components`/`canAdd`/`addComponent`/`removeComponent`/`setParams`/`setComponentEnabled`; on an inherited node each of them writes a **`NodeOverride`** instead — params, enabled, added or removed — with `overridesOf`/`revert`/`applyToPrefab` behind Revert and Apply. `setTransform` replaced mutating what `transformOf` returned, since for an inherited node those are different objects. The **Inspector generates its own fields** from each component's declared parameters and offers an add-component picker filtered by `canAdd`, so a new component type needs no edit here; an overridden parameter is marked with a leading `•`. **Selection** is `selection.ts` (ADR 0031): a `number[]` with the primary **last**, so everything with one subject (Inspector, timeline, track helper) still reads a single index while transform/delete/duplicate/copy read the list. `modeFor` maps Ctrl→toggle and Shift→range; `rangeIn` runs over the panel's *visible* row order, not over indices; `rootsOf` drops a child selected alongside its parent, which is what makes delete and duplicate safe. Shift-range is Hierarchy-only — the viewport has no order to range over. **Keyboard** is `shortcuts.ts` (ADR 0030): bindings are a table of `{id, chords, label, run, enabled}`, matched on the **character** a key produces (`e.key`) with `e.code` only as a fallback for non-Latin layouts — so Ctrl+Z is the key marked Z on AZERTY, not the one where QWERTY puts Z. A disabled binding does not consume the key, which is what keeps WASD working during play. `history.ts` is **undo/redo by whole-document snapshot** (root document only; one entry per gizmo drag; no-op edits dropped by comparison; selection restored by sibling path), and `Doc.copy`/`Doc.paste` are the **clipboard**, which carries the prefab definitions a copied instance references so a paste is self-contained across files. **Animation** is the timeline strip in the bottom row, and it edits **one component's `keys` parameter** (ADR 0037): `Doc.keyEditors`/`keysOf`/`setKeys` address a `(node, componentId, param)` triple rather than "the selection's track", the strip is opened by **Edit keys** in that component's own Inspector section and names what it has open, and `loop`/`phase` live only in the component's section since they are declared parameters like any other. `trackEdit.ts` is every timeline mutation as a pure function, 16 of them with 55 tests (put a key or one channel, retime one channel with a **split** when the key holds both, shift a selection as a group, delete/copy/paste, easing, snapping, channel rows and segments, path points); `timeline.ts` is a **dope sheet** (ADR 0051): a lane per channel, a pixel time axis with wheel-zoom about the cursor and shift+wheel/middle-drag pan, box-select, multi-key drag, a typed row for the primary key, scrubbing on the ruler, and **Record mode** — armed, a gizmo drag writes a key at the playhead on the channel the gizmo mode moved. `writeKeys` is the single seam every key write goes through, so a drag can never write inline keys onto a node playing a clip; the clip's sibling parameter is named by the `keys` declaration (`KeysSpec.clip`) rather than assumed, so ADR 0037 still holds. Clips are editable in place, tagged in the toolbar, with Save as clip / Unlink and a 400ms debounce to disk — **not undoable**, since history snapshots the document and an asset is not in it, exactly as with a material. The viewport draws the **path** with a draggable handle per key. The gizmo writes **the selected key's offset when a key is selected, and the authored transform otherwise** — animated or not, since keys are offsets and the whole path rides the transform (ADR 0050 collapsed ADR 0029's third row, and with it the per-key delta rewrite and the drag snapshot it needed). `assetOptions(of)` feeds every asset-valued parameter from one accessor, and the Project panel's `+ new material` generalised to `onCreateAsset(kind, folder)` so an animation clip can be made empty there too; the library loads `*.anim.json` alongside materials and prefabs and satisfies `ClipSource`, so the viewport plays a clip a `Track` names. **The timeline opens a clip directly** since ADR 0051. Placement **overrides** are per node and per component (ADR 0035), structural ones included. **Right-click menus** are one module, `menu.ts` (ADR 0040): an item is `{label, run, enabled, why, hint, items}` — the same shape as a `shortcuts.ts` binding, so a command is described once and the menu shows its key. Submenus open on hover or ArrowRight; placement **flips** rather than clamps (`menuPlacement`/`submenuPlacement`, pure and tested) so the first item is never under the cursor; a refused operation stays greyed with a reason rather than vanishing. It serves the Hierarchy (row, and blank space), the Project panel — replacing a `prompt()` in which clearing the name deleted the file — the Inspector's `⋯`, the timeline's key menu, and the viewport, which opens on the pointer **release** because OrbitControls pans on right-drag. Three commands exist for it: `Doc.placeEmpty` (a grouping node, which nothing could make before), `focusSelection` (frames along the camera's current direction, also bound to `F`) and `pasteAt` (the group lands where you clicked, keeping its offsets). **Which game it is authoring for is explicit** (ADR 0052): `modes.ts` globs `modes/*/src/editorMode.ts`, a toolbar **game picker** sets the authoring context (narrowing the level list on `config.mode.name` and deciding what a new level is for), and a **Game row** beside Environment is where a level is reassigned — one dropdown, since a game declares no level settings (ADR 0053). Everything mode-shaped comes from the descriptor: the registry the document is validated and edited against, the rule gizmo colours, and play-in-place, which runs the game's own `session` rather than a copy of its rules. A level naming an uninstalled game still opens, with the row saying so. Save syncs the file name to the document id — and, in prefab mode, to the root node's name. Reads/writes `content/` via a dev-server file API (which now returns `[{ name, mode }]` for levels, so a picker needs no per-file fetch).
- `modes/parkour` — **six files** since ADR 0056: `main.ts` is 12 lines that hand `PARKOUR_MODE` to `startGameClient`, `editorMode.ts` is the descriptor, `rules.ts` is its rules (headless), and three test files guard its rules, its levels and its asset references. Everything below this line moved to `@mp/game-client` and is described there; it is kept as the record of what the mode *contributes* rather than what it contains. Historically: the parkour mode on Colyseus rooms: Roblox-like controller (live-tunable), auto-join, nametags, data-driven levels, checkpoints/hazard/fall via physics triggers + persistence adapter, a **death ragdoll** + **spawn assembly** (one dynamic body per rig part, seeded from the animated pose; left click respawns and the body drops back in a pair at a time — ADR 0019; peers ragdoll and re-assemble too, each viewer running its own from one `STATE_DEAD` flag), a **Pixi pause screen** (settings + roster + restart, localized via `@mp/i18n`), and the **third-person camera** (wheel zoom, pitch to straight overhead, sphere-cast occlusion — ADR 0020 — with `cameraOcclusion.ts` deciding per frame whether an obstruction moves the camera or dithers away, ADR 0055). **Level selection** in `levels.ts`: `?level=<name>` loads `content/levels/<name>.json` (bundled via `import.meta.glob`), no param loads **`default.json`** (a placeholder so the game always boots; a file, so the editor can edit it — ADR 0027); an unknown name logs and falls back to it. The name is passed to `joinOrCreate` as a matchmaking filter. `assets.ts` builds the asset database from bundled `.meta` sidecars and preloads what a level references before the level view is built (ADR 0026); it also exports `CLIP_SOURCE`, the bundled animation clips as the `ClipSource` `instantiateLevel` takes (ADR 0050). `references.test.ts` is the **reference-integrity guard** (ADR 0028): every material/model id reachable from every shipped level resolves in `ASSET_DB`, every texture a material names resolves, and the seven greybox materials exist by name — a dangling id greyboxes silently, where an unknown `style` used to fall back harmlessly. Composition root; view pieces in `nametag.ts`/`characterView.ts`/`pauseMenu.ts`/`ragdoll.ts`/`assemble.ts`, collision layers in `layers.ts`.
- `content/levels` — level JSON **as node trees** (ADR 0035), loadable by name (`?level=<file>`):
  **`default.json`** (what loads with no param), `level1.json` (the ported original world), plus
  editor/Unity scratch files. `content/assets/prefabs/*.prefab.json` are root **nodes** for the same reason.

## Deferred (not built)

- **Mobile is playable but unmeasured and unvalidated on a device.** Touch controls exist and are wired
  (ADR 0022): stick bottom-left, jump bottom-right, look everywhere else, pinch to zoom, tap to respawn
  while dead. What has *not* happened is anyone playing it on a phone — so the layout numbers are first
  guesses (all exposed in the pane's **Touch** folder), and budgets 1 (frame time) and 5 (memory) are still
  unmeasured, which needs the same device session. The pause screen is the only UI laid out for a small
  screen; nothing else has been sized for one.
- **Nothing verifies a level is clearable.** `gym.test.ts` asserted every authored jump against the
  measured envelope; it and its subject are deleted (ADR 0027). The envelope is still measured
  (`packages/character/src/envelope*.test.ts`), so the numbers in `obstacles.md` hold — what is missing is a
  check over an authored level, which belongs in the editor as a reachability gizmo.
- **Parametric generators in the schema.** A prefab file stores baked pieces, so it cannot hold
  `padChain({ gap: 2.5 })` — only the boxes it produced. Considered and rejected when the generators were
  deleted (ADR 0027): shapes like a pad chain or an arc now have to be built piece by piece, since scaling
  cannot change a pad count or an arc radius.
- **Shared mutable component state (stage C5).** Components run (ADR 0036), and everything they can do is
  either pure or **local** — a rule that reacts to my contact and changes my character needs nobody else to
  agree, which is why every rule that exists cost nothing in netcode. What is *not* built is anything whose
  state every client must agree on: a door that stays open, a button, a pushable crate, a dynamic rigid body.
  That needs an owner and a sync channel — a netcode milestone, not a component, and explicitly Kodjo's call to
  open. `Ctx` gives no reach to do it, so the boundary is enforced by the API rather than by this paragraph.
- **No per-frame component hook.** Deliberate (ADR 0036): gameplay that reads frame time desyncs by
  construction. A render-step hook for purely cosmetic components is the obvious later addition, gated so it
  cannot touch the character.
- **No goal rule.** `Goal` is a component and `default.json` has a goal pad, but it carries no hook and nothing
  ends a run.
- **Other modes** (obby-tower variant, keyboard-run grind + progression), **glTF art layer**, **account-backed persistence** — accounted for by seams (ADR 0014), not built.
- **M9 — 2D path** (Rapier2d + Pixi-only). Deferred when scope narrowed to 3D.
- **Deploy** (Dockerfile + single-VPS) — re-scoped with Kodjo when a target exists. `infra/` empty.

## Where "SEED §n" points

`SEED.md` was Kodjo's requirements handoff — locked decisions, the five budgets, the structural laws, the
build order. It was **input to the project, not documentation of it**, and by its own lifecycle note it was
deleted once every part of it had been implemented and documented or explicitly superseded. Git has it.
